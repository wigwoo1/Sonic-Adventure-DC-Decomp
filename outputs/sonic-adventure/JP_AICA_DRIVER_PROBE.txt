Actual ARM sound-driver execution and game-bank audio on native Windows
Whole-project estimate: approximately 10%; goal active.
Status: VERIFIED PRIVATE PROBE; full original SDK/game audio integration open.

Concrete result
The original 33,376-byte MASARU ARM program executes on a pinned reusable ARM7/
AICA core. With actual EMERALDCOAST.MLT bank data and SDK-format note commands,
it generates 88,200 stereo frames of nonzero signed16 audio. The actual driver
changes its command-list status from waiting to ready; there are no instruction
hooks, scripted statistics or replacement note synthesizer. Converted PCM is
delivered to the previously qualified real Windows render client in a queried
muted session, with an independent float-packet hash and actual clock drain.
No microphone/loopback capture or system-volume changes are involved.

Scope of qualification
Final build: work/sonic-adventure/jp-aica-core-probe-v10 (2 MiB RAM).
Larger-RAM control: work/sonic-adventure/jp-aica-core-probe-v9 (8 MiB).
Final verification: work/sonic-adventure/jp-aica-driver-check-v7.
Three fresh-process cases pass 1,010 assertions. Each executes 44,100 silent boot
frames, 88,200 note frames and 44,100 post-note-off frames. Both 441-frame packets
and varied 3..8191-frame packets give identical note/tail PCM, complete final
2 MiB RAM images and ARM register snapshots. The two RAM sizes use the same
ordering fixes; the larger control is not an unmodified hardware oracle.
Independent authored ARM load/store instructions also verify 2 MiB mirroring.
State, ARM pointers and callbacks remain native-width, with surrounding canaries.

The real Windows output consumes all 88,200 generated frames with no drop or
duplicate and matches the expected copied/normalized PCM hash. The sender may
overwrite its float buffer as soon as submission returns. This reuses the actual
owned native audio worker and its safe drain/close; no new output stub is used.
Playback through physical speakers and console waveform accuracy are unmeasured.

Resolved ordering defect
An initial check found identical output audio but packet-dependent DSP work RAM.
The original ARM registers and total executed cycles already agreed. Simply
ordering ARM RAM stores before pending AICA processing did not fully resolve it.
A second focused change also advances AICA DSP state when effects are inaudible
and flushes pending samples before effect-send/pan changes. With all three rules,
complete RAM and output now agree across packet sizes. DSP processing remains
enabled. Checks were not changed to ignore the differing RAM region.

The generated native copies implement:
- Two MiB allocation, upload/access masks and Yamaha sample-memory size, with
  mirroring in the core's existing ARM RAM window. The pinned game SDK declares
  SD_SND_MEM_SIZE=0x200000. A larger-RAM control isolates this adaptation.
- ARM RAM-store callbacks that synchronize and flush before modifying shared RAM.
  Instruction fetch and ARM RAM reads retain the external core's direct maps.
- AICA DSP advancement independent of audible effect sends/output availability,
  and a flush before effect-routing changes.
Broader read coherence, register behavior and timing still need qualification.

Earlier failed runs, generated sources and source snapshots are preserved. One
test incorrectly assumed the post-note-off output must be exactly zero; actual
output retains values up to 4/32768 at the end of the measured tail. The final
test compares the entire tail against the control and reports that residue.
Acknowledgement alone is not presented as envelope or physical-hardware proof.

Reused source, provenance and build limitations
External core: https://github.com/kode54/Highly_Theoretical
Pinned revision: 2998a4bf550949cd2daee249e725a64462cf15e0
Its source and GPL-3.0 license are available at that pinned upstream repository.
Both downloaded/review and canonical native checkouts remain local. The first
Windows checkout converted license line endings; the provenance guard rejected
it before compilation. A new canonical checkout preserves the Git blob bytes.
The external checkout is unchanged; all adaptations are generated privately.

Three external C units and an authored API fixture compile/link on Windows x64.
The fixture and link produce zero diagnostics. The external units retain 17
warnings about unused members/functions and signed comparisons; these logs are
preserved and not described as warning-free. An initial link requested arm_setreg,
which the external header declares but source explicitly leaves unimplemented;
the probe no longer requests that unused export and provides no fake implementation.

The inherited interpreter policy is 128 cycles per 44.1 kHz frame. Physical ARM
cycle timing has not been qualified; do not infer it from the sample rate or
successful commands. The reference/control both use this policy. Physical
waveforms, all banks/voices, PCM streams and full DSP behavior remain open work.
This is a sound-hardware probe within the native-port effort, not game emulation
in place of compiling the game's recovered source.
