What changed
The missing pdInitPeripheral SDK entry now initializes the existing native
keyboard/XInput or explicitly selected sample provider. No second input singleton
or duplicated controller backend was added. The native coordinator configures
the actual borrowed HWND/flags/provider before calling the original signature.
The old receive/send pointers describe Dreamcast Maple DMA transport. Native
code never reads, writes or retains them; PC services are actually acquired.
The SDK entry is void, so callers must check jp_input_bootstrap_status before
using input or continuing startup. Missing configuration, bad window, unavailable
service and duplicate initialization cannot become successful startup.

All 24 SDK ports now have stable distinct native records: four controller roots
and their expansion positions. SDK reset initializes fields and the original
"(no device)" name using active or negative logic. Logic 0 and 1 are supported;
other values explicitly fail. Actual polling preserves positive/negative edge
semantics and separate physical history so game demo/recorder overlays cannot
fabricate input transitions. The direct native initialize API retains its
qualified pre-poll sentinels and positive-logic behavior. New SDK error lookup
reports a real unavailable/failed owner, not a fabricated successful device.
This is an authored native SDK replacement. Original pdmain initialization is
an independent instruction oracle, not another compiled Kaede hardware backend.
Raw keyboard devices, light guns, vibration and other Maple commands are not
implemented by this controller/VMU bootstrap result.

VMU attachment metadata
An optional metadata provider projects actual storage/LCD/timer descriptions
into the SDK expansion records. The virtual-card bridge reads the existing real
VMU store and qualified LCD/Kaede metadata owner; it does not invent another
card image or storage writer. VMU store/LCD initialization can follow input
initialization. Before those owners are ready, no card is advertised. Each poll
then observes actual insertions/removals at ports A1/A2 through D1/D2. Cards are
advertised according to the existing LCD owner's enabled/attached endpoints.
The bridge copies the 120-byte metadata record instead of aliasing distinct
SDK structure types. Storage, LCD and timer are the supported expansion types.
Controller samples and all metadata are validated/staged before committing
records. A late metadata failure or unsupported type leaves the last committed
records intact and exposes an error. Input shutdown leaves VMU/LCD owners alive
for their separate cleanup. Borrowed metadata callbacks must remain valid until
input shutdown; shutdown also cancels pending configuration, preventing stale
callbacks/window handles from leaking into later initialization.

Ownership
One creating game thread owns pending configuration and live input. Foreign
calls cannot steal pending callbacks or close the owner; recursive poll/shutdown
from either controller or metadata readers fails. Original SDK exit closes the
real input owner and clears borrowed configuration. General native exit already
selects this same input owner. It continues to remove RTC before device/wait
shutdown and free the SDK heap after consumer destruction. The new input work
does not create another final-close authority for those services.
