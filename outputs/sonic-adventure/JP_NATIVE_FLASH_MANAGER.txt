What is real

The complete pinned sdk/shinobi/fm.c and fmcrc.c translation-unit bytes are
preserved inside private generated source. The nine public FM entry algorithms
and original CRC table/routine execute with their actual single cache/request
owner. Private name macros permit bounded native guards around those entries.
The SDK headers load before the original GCC map-byte branch is enabled, so
the x64 compiler does not accidentally select SH-4 inline assembly. No boot-ROM
syscall assembly is compiled or falsely reported as functional native code.

Four authored native flash calls replace only the hardware/storage boundary:
partition information, byte reads, programming and containing-sector erase.
A new profile may explicitly create an all-erased 128KiB SONIC_FLASH.DAT in
an existing directory. It contains no imported BIOS, factory identity or retail
save data. Existing files are never automatically reformatted. Factory-region
programming/erase is refused. Programming clears bits; erase restores ones.

Partition geometry references (facts only; no emulator implementation copied):
https://github.com/KallistiOS/KallistiOS/blob/master/kernel/arch/dreamcast/include/dc/flashrom.h
https://github.com/flyinghead/flycast/blob/master/core/hw/flashrom/flashrom.h
The five partitions retain their 8/8/16/32/64KiB sizes and normal raw offsets.

Persistence and ownership

The creator thread owns the profile and original manager. An exclusive real
Windows sidecar handle prevents a second process taking the same profile.
Each primitive reloads the image, checks for out-of-band changes, writes a
temporary whole image, flushes it, and replaces the target with write-through.
Only after success does committed in-memory media change. Actual OS failure
and counters remain visible. Failed temporary outputs are removed; original
profiles are preserved. Close/reopen releases and reacquires the actual lock.

The caller supplies sufficiently sized/aligned original FM work and request
buffers. They stay borrowed through completion or explicit fmMngFinish.
Native close and conflicting init/format/refresh reject a pending request.
Direct raw mutation cannot bypass a live original manager. Wrong-thread calls
preserve real state and diagnostic output buffers. Original fmMngFinish keeps
its explicit cancellation semantics: after the erase phase it can leave the
sector erased. This is tested and is not called successful persistence.

Atomicity is per native primitive, not a transaction around a complete original
packet write, format or safe-refresh sequence. The original FM algorithm can
change its working cache before an I/O failure. After correcting an OS error,
the caller must clear the native error and reload/reinitialize the real cache
from disk before treating its contents as persisted truth. The UF safe-refresh
and complete application shutdown ownership still require later integration.

Verification

739 direct assertions passed in 11 fresh subprocess cases. Separate child
checks also prove cross-process lock rejection and reopening persisted packets.
No user save file or retail flash dump was used.

- Original table CRC matches an independent CRC implementation for 513 input
  lengths. An independent raw-image decoder validates headers, maps, latest
  packet selection, full payloads and CRCs.
- All partition geometries/capacities and work-buffer bounds; factory
  protection; one-to-zero programming; whole-sector erase; argument bounds.
- Request exclusion, live borrowed buffer use on first service, explicit
  pre-service cancellation and original protected-format behavior.
- A full 510-record history log runs the actual append/erase/store phases and
  compacts to two latest packets. Reopening reconstructs the original cache.
- Corrupt CRC/out-of-range records are ignored during cache load; corruption
  of the actual working cache reports the original read CRC error.
- Real Windows denial of replacement produces original write/erase errors.
  The entire prior image and committed media counters remain unchanged. A
  corrected condition permits real reload/retry and a verified disk commit.
- External image changes, foreign thread access, invalid existing profile
  size, actual lock release and explicit cancellation after erase.

Next required integration

loader_note_error, main-owned mode/error data and Sofdec platform preinit.
