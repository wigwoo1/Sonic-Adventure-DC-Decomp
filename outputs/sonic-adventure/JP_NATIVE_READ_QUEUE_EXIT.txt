What changed

System can start the actual original background file-read queue and attach its
cleanup authority to the existing bootstrap registration. Explicit guarded adopt
can also hand off an initialized, unclaimed queue. Automatic startup preserves
an existing independent owner; explicit adoption rejects another claimant before
changing System resources. No second bootstrap callback/registration is created.
The earlier original five-function queue object and native GDFS DLL are unchanged.

The same queue owner now carries a monotonic terminal token. Data operations
continue while delegated, including after final Exit binding. Once close begins,
application mutation, replacement and independent shutdown are rejected. A failed
close retains the exact original slots, caller destinations, selected file handle,
native GDFS client lease and lifecycle token. The authority can retry the genuine
close. Terminal finish cannot cancel or restart; a completed ordinary close may
release its nonterminal claim after the whole ordinary System shutdown succeeds.

The new explicit mask bit JP_EXIT_READ_QUEUE is 8388608. Existing masks retain
their meanings. Final binding requires the queue bit/token and transfers the
same earlier token only after every other final claim succeeds. A tested later
device-claim rejection preserves the real bootstrap and queue authority.

Both ordinary/early System cleanup and final Exit drain CARD first, then the
READ_QUEUE, then HISTORY, SOUND, GDFS and RTC before remaining device/heap owners.
Actual card callbacks can still enqueue file work and record history while they
drain. Callback attempts to finish the queue are rejected using real card
activity. Queue/GDFS callback activity is checked before irreversible terminal
flags or cleanup counters change. No separate imitation callback counter is used.
The bootstrap callback's original body remains unchanged.

Real failure and retry

The tests temporarily remove the genuine GDFS vblank handler while a real file
read is pending. The actual checked file close fails, leaving the original slot,
destination, handle and GDFS lease live. History, sound, RTC and GDFS ownership
remain available. Restoring the same original callback/argument/priority at its
expected native handler ID allows the real full cleanup to retry and succeed.
The original allocator fills any needed lower holes without dispatch; temporary
handlers are removed immediately. No successful file-read/close substitute or
original-function hook is installed. This failure is a missing native service;
it does not claim to force an OS cancellation timeout.

A separate real Windows sharing denial causes history persistence to fail after
the queue has already closed. The old complete profile remains unchanged, and
the queue is not closed twice on retry. Another case makes ordinary shutdown
stop at that history failure, then succeeds through global terminal cleanup;
the already closed queue's existing token becomes terminal safely. Caller buffers
remain live until actual queue close succeeds, and the retired reader cannot
write them afterward.
