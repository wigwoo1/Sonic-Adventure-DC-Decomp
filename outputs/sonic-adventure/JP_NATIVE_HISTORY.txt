Native original play history over owned transactional flash
Scoped qualification, 2026-11-06; whole project approximately 10%.

Status: the exercised history lifecycle is VERIFIED. Full game_init and its
global System/Exit history handoff remain unfinished. This is not a playable
native PC port. Matching/GCC source baselines remain preserved; localization,
full gameplay, settings and later-platform goals remain incomplete.

What now executes

The original UF library, game history.c, disc-identity parser, Ninja word-copy
routine and character table link with the actual existing FM/CRC, RTC and
peripheral providers. An owned native service runs the original history
constructor, save, read and character counters. It allocates real refresh work
instead of dereferencing WORK_AREA. The original game's own static work1/work2
and counter table remain single instances. RTC/input/VMU remain borrowed owners.

The boot identity is parsed by the original algorithm from an actual local
Japanese track header copied into owned memory. No boot ROM address is touched.
Only an actually newly created native profile can be initialized: shared flags
and a 240-byte title record use the real original parity, FM packet writes and
CRC. Existing malformed/unknown profiles are rejected without autoformatting.
A new profile starts with StartCount=1. Per-launch BIOS accounting is not yet
implemented; reopening preserves that field. This component does not import
console BIOS/factory dumps or user save files.

Explicit adaptations

- ufGetUserState's address parameter and declaration use intptr_t. The actual
  original word-copy runs against a high native address, with canaries checked.
- The old flash helper loop stored a Boolean and could report success when the
  server failed. It now checks the actual completion status. Ignored failed
  initialization, clock, packet, flag and refresh-status calls are propagated.
- UF expects an empty type-zero description for an unplugged expansion socket.
  The native bridge derives that absence from the actual input record's
  id=0/info=NULL; attached controller/VMU metadata remains the genuine provider.
- RTC startup checks actual initialized state. Successful RTC reads return
  nonnegative mode bits, which are preserved rather than misread as failures.
- The original history read reinitializes UF from disk. The native boundary
  first saves dirty live history so that read cannot discard pending data.
  Failed reads/checkpoints preserve caller output arrays.

The audit identifies all 51 original functions in this closure: 32 bodies are
unchanged and 19 have explicit native pointer/error adaptations. Original UF
quirks outside these changes remain, including character-count wrap and the
safe-refresh success errno. Unused title-delete/network/auto-save APIs remain
linked but have not been qualified as application features. No successful SDK
producer, clock, filesystem or peripheral result is fabricated by the tests.

Native transactions and failure ownership

The actual flash owner gains a monotonically increasing history capability.
Legacy FM mutation/finish, raw mutation and profile close cannot detach its live
UF work. Authorization surrounds each individual FM call and is released before
any RTC callback. History reentry and foreign-thread calls fail before mutation.
The dependency direction is History -> Flash/Frames/RTC; Flash imports only
Windows libraries and neither module imports System/Exit/MainBoot.

Each save, read checkpoint and original safe refresh stages the real FM
program/erase operations against an owned image. At commit, the previous disk
image is revalidated, then the complete staged image is flushed and atomically
replaced. Only successful commits retire rollback media and publish committed
write counters. A failed commit restores the entire prior image and closes the
discarded FM cache. UF/live work, dirty data and the profile capability remain
owned for explicit recovery/retry. Empty read transactions do not rewrite disk.
The immutable earlier flash qualification describes per-primitive atomicity;
this extension additionally makes these history operations whole transactions.

Shutdown flushes dirty history before releasing its original cache, capability,
profile lock and native work. A failed save/shutdown leaves those obligations
intact. The caller must keep RTC/input alive, correct the underlying condition,
call recovery, then retry. Existing global Exit does not yet own this new
service: close history before the caller's System/RTC/input teardown.
