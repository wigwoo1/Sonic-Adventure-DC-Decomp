Why preserve the original formatter

The runtime has source-documented SHC behavior that differs from standard PC
printf. For example, %.2f of 0.125 is 0.13; %-05d of 42 is 42000; %#06x of 255
is 000xff. %g chooses its style/counts precision differently. Reusing the
original formatter preserves these behaviors, including original finite-value
rounding, padding, integer length modifiers and strings. Only native argument,
buffer and numerical boundaries are adapted.

Windows native varargs use compiler builtins. Integer/long values remain 32-bit;
strings and %n use real native-width pointers. %p preserves the original 32-bit
display value (low 32 bits of a native pointer). Floating arguments arrive as
native doubles, then narrow to the original single RZ/DN1 value and widen exactly
for the original decimal helpers. The _log10 body retains its splits; its
exponent*0.301L result is replaced by an exact integer service over the complete
widened-single exponent domain, -125..128. Every exponent matches whole original
code execution. No new host FP arithmetic is present in the authored boundary.
FPSCR flags/traps, host floating flags, console timings and whole-game FPSCR
contexts are outside this fixed value-only qualification.

Bounded native policies

Formatting is owned by one game thread. Caller buffers must be valid writable
storage, 1..32,768 bytes including the terminator. Format and string arguments
must be valid and terminate within 32,767 characters. The original formatter
retains its 512 width/precision limits. Every string emission and NUL write is
checked against the supplied buffer. Failures return -1, clear the output string
where a nonzero valid buffer exists, and expose jp_print_format_status. The
original formatter's errno state is namespaced away from the host CRT.

An invalid/truncated directive, INT_MIN star width, negative emission length
from the original alternate-hex-zero bug, null string or excess output becomes
a native formatting error. The carry/zero-fill loops check their bounds before
reading or stepping outside arrays. %n retains its original count-store semantics;
callers must provide valid writable int pointers, and such stores can precede a
later formatting error. Undefined or overlapping caller storage is not emulated.

njPrint keeps its 128-byte local buffer: at most 127 output bytes fit, and failed
formatting produces no queue draw. njPrintF preserves its 20-byte local buffer
and five decimals, accepts finite values and digit counts 1..13, and checks that
the rounded integer part fits the requested digits. Oversized values, nonfinite
values or negative padding produce no draw. Valid negative values still emit
their sign separately, as the original does. Signed zero and subnormal handling
follow the fixed original value policy. Existing real print size/colour state,
16-bit coordinate wrapping, metadata preservation and frame retention remain.

Reproduce locally

Use Windows Clang/SDK and Python 3. Set PY/CLANG to local executables; use fresh
output paths. Retain the previous print-v7 link recipe, pinned upstream commit
25a3d3154dbe657325e97dbe8c5291086f6af5c0, and authentic private font include.

& $PY -B outputs/sonic-adventure/jp_port_tools/build_native_print_format.py --workspace . --upstream work/sonic-adventure/reshaped-sonic-adventure-review --baseline work/sonic-adventure/jp-native-print-v7 --compiler $CLANG --output work/sonic-adventure/jp-native-print-format-v3
& $PY -B outputs/sonic-adventure/jp_port_tools/verify_native_print_format.py --workspace . --upstream work/sonic-adventure/reshaped-sonic-adventure-review --build work/sonic-adventure/jp-native-print-format-v3 --binary work/sonic-adventure/jp-ninja-math-reference/1ST_READ.BIN --font-input work/sonic-adventure/jp-native-built-in-font-atlas-v1 --output work/sonic-adventure/jp-native-print-format-check-v4
& $PY -B outputs/sonic-adventure/jp_port_tools/package_native_print_format.py --workspace . --build work/sonic-adventure/jp-native-print-format-v3 --verification work/sonic-adventure/jp-native-print-format-check-v4 --compiler $CLANG --output work/sonic-adventure/jp-native-print-format-support-v1
