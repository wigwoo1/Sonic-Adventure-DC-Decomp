Original code and a historical mismatch
8c604594 is a ten-instruction leaf. It loads a05f810c, then the original 16-bit
literal at 8c604618: 01ff. It reads status into R2 until the low nine bits are
zero, then into R3 until those bits are nonzero. T, registers, exact read order,
return and delay slot are retained in source/sa_movie_transition.c.
KallistiOS identifies the register at offset 010c from a05f8000 as sync status:
https://github.com/KallistiOS/KallistiOS/blob/master/kernel/arch/dreamcast/include/dc/pvr/pvr_regs.h
The game's exact phase/order and mask come from its own original instructions,
not from a replacement wait implementation or a copied KallistiOS routine.

The old source/packet_mmio.c helper used ff0f01ff, testing additional high bits.
Its earlier 25 selected sequences did not distinguish those masks. We retain
that source, original proof and compiled DLL unchanged as historical artifacts.
The new complete-state path uses the actual 000001ff literal and does not call
the old helper. Twenty-three outside-field bit cases compare against original
instruction execution; twelve show the old helper takes four reads when the
original and new native path take two. Its old evidence must not be interpreted
as proof of arbitrary 32-bit status behavior. New registry integration metadata
records this limitation and identifies the preferred corrected native source.

Native timing input interface
source/display_timing_bus.c/h wraps the existing A/V/cache/peripheral interface.
The caller supplies borrowed raw 32-bit SPG_STATUS observations. Every supported
read consumes one unchanged word, stores it in the existing register bank and
records the original address/raw value. Unsupported widths, null output and
writes are rejected without state changes. Physical/P1/P2 aliases use the
inherited address normalization. Exhaustion returns host status -4 at the
reached read; it does not generate a clear/busy transition or a game result.
Reconfiguration starts a new observation stream; the caller retains ownership
and must keep the sample storage alive until reconfiguration/reset.

This is an explicit input boundary for native integration and comparison.
It does not generate scan timing, synchronize a PC display, deliver physical
IRQs, emulate electrical devices or render pixels. A real host presentation
clock and the requested 60/120/240 FPS behavior remain future port work.
