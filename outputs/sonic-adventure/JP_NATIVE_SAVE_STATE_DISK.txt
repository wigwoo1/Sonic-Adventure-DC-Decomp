Full Japanese save state and native Windows disk persistence

Overall estimate: about 10% of the complete project, using weighted milestones.
Goal active. Japanese source baselines are verified. Full native gameplay,
English localization, enhancements and later platforms remain unfinished.
These are incomplete research artifacts; there is no playable game executable.

What changed

The entire unchanged original src/save/save.c from external upstream revision
25a3d3154dbe657325e97dbe8c5291086f6af5c0 is linked into the shared frame/game
owner, replacing the earlier partial save-reset owner. Original defaults,
ring_reset and shared demo/slot/ring state remain single definitions. Seven
actual progress/stage declarations now provide shared runtime storage:
stage_clears, event_flags, story_records, dat_8c7a2718, events_played, lives,
play_time. Original save.c owns saves and stage_last_cleared exactly once.
The intentionally unused original save_stage_lists table requires the scoped
-Wno-unused-variable compile exception; the upstream source is not edited.

The new authored jp_native_save_disk support library imports this genuine
shared state. An existing Unicode directory contains SONICADV_JP.SAV: three
original 1,184-byte Japanese records, 3,552 bytes total. No disc/card wrapper
or retail asset is embedded. save_store/save_update must be called explicitly
by the owner before writing when a progress snapshot is desired. Reading only
updates serialized snapshots; apply(slot) invokes genuine save_load to restore
active progress. The service does not initialize the game or drive its menus.

Writes validate the original CRCs and character bounds, write and flush a
same-directory temporary, close it, then atomically replace the target. Failed
replacement preserves the previous file and removes the service's temporary.
This is tested for actual Windows file locks, not a guarantee against every
storage failure or power loss. Reads validate exact length, all CRCs and all
character indices before modifying live state. CRC alone does not prevent an
out-of-range character from indexing the original lives table. Other game
fields retain original behavior: this is not a complete semantic validator
for every possible scene/script. The format is version-specific, not an
English/USA-compatible save promise. Unknown bytes are preserved.

One game thread owns the service. Errors stay set until clear_error or shutdown;
foreign threads cannot clear or mutate owner state. There are no persistent
file handles. Call disk shutdown before shutting down the shared game owner.
VMU/menu/card callbacks and the full game main loop are not yet integrated.

Reproduce locally (PowerShell, workspace root)

Use Python 3, the previously qualified boot-saves-v3 dependency chain, the clean
pinned external source checkout, a matching privately supplied Japanese game
binary and asset fixtures. Source and proof manifests record exact compiler,
input and dependency hashes. The public research archive alone cannot run the
private game-containing diagnostic DLLs. Existing guides explain prerequisites.

Set PY to your Python executable and CLANG to qualified Clang with the Windows
SDK/linker available. Choose fresh output directories for each run. Example:
