Build and verification
The 164-source movie_driver.dll compiles with Clang -O2 -Wall -Wextra -Werror,
without the C runtime. Ninety original-instruction/native comparisons pass:
49 normal returns, five reached-memory faults, five missing-service/platform
stops and 31 explicit research/privilege/input stops. There are 337 independent
semantic checks, 98 bus API checks and six retained startup profiles / 120 checks.
Comparisons retain complete 16 MiB RAM, CPU, both FPU banks, special/banked state,
ordered boundaries, software registers, VRAM and finite input cursors. Coverage
is reported separately for each body; proposals are not automatic recovery.

The raw normal-IRQ-status stream is a borrowed finite array of 32-bit words.
Each valid read consumes one observation, exposing that last status. Writes keep
the old write-one-to-clear acknowledgement. Empty/exhausted reads return host
-4 before changing cursor, last status, output or trace. Unconfigured reads keep
the old stored-status policy. Physical/P1/P2 aliases and rejected widths are
checked. No completion event or interrupt delivery is invented.

DMA operation register ffa00040 has explicit software word storage, with trace
29 reads / 30 writes. It does not execute DMA or reproduce physical hardware.
Raw PVR ID/revision observations, FIFO/scan/clock samples, VBR/runtime state and
existing host fixtures are declared inputs. The original clock routing survives.

The original clear invokes helper 8c65253e 2,097,152 times, writing eight MiB.
Full per-boundary state hashing makes this prohibitively expensive for the
current verifier. With SA_BOUND_RETAIL_STALLS, the research DLL stops at
8c665998 before its second continued loop test, after two actual word copies.
The original hardware-failure infinite loop 8c665968 similarly stops on its
second visit. Without that macro both original loops remain unchanged. Syntax
checking covers all 164 sources without the macro. These limits do not establish
completion of the clear or its callers and must not become port behavior.

Both early-caller profiles execute real original code that creates heap root
8c88ef1c and renderer root 8c8a2d54, then stop at the bounded clear. The original
early caller 8c010180 stays partial; no later startup stage is silently chained.
Six separate late-boot controls retain their genuine zero heap and prior faults
8c6021fe / 8c10d4bc. They do not claim to run completed early startup.

Driver R4 is mode/size flags, R5 is pixel format, R6 the additional configuration
word, R7 extra input. One invalid-mode profile follows the real mode error return
and subsequently stops at the actual unresolved indirect callback 8c000000.
No callback result is substituted. Full natural boot, rendered pixels, gameplay,
requested FPS/8K/display settings, SUPIR textures and other ports remain pending.
