New boundary
jp_native_aica.c owns a guarded native emulation state and, when explicitly
requested, a real 44.1 kHz Windows audio worker. Configuration is copied. One
creating thread owns operations; foreign callers cannot access or close it.
Native pointers stay full width. Sound RAM is exactly 2 MiB and API bounds do
not silently wrap. Original sound-memory offsets remain 32-bit values.
The ABI is a 32-byte options record and 104-byte diagnostic snapshot.

The API supports copied/unaligned RAM access, chip register access, CPU reset,
offline signed16 stereo rendering and actual device pumping/draining. Offline
mode is explicit and cannot claim device delivery. The core begins with the ARM
held in reset; rendering while held advances AICA/DSP/timers without running CPU
instructions. CPU reset preserves RAM and sound-chip state, while a full close/
open creates a fresh context. The inherited128cycles/sample interpreter policy
and wider core/hardware behavior are still provisional.

Pump checks actual output queue capacity before executing the core. A queue-full
result leaves emulated time unchanged. A core/device failure is explicit; failed
rendering does not copy a partial PCM buffer to the caller. Close cancels queued
audio through the actual audio-worker join. A bounded timeout retains both core
and output resources until the same close is retried. Explicit drain is separate.
Pre-existing audio sessions are rejected and never adopted or closed by this owner.
This local owner has not yet been added to the game's global System/Exit registry.

Reset defect found and corrected
The first held/released CPU test failed: a pending chip interrupt diverted the
CPU before its initial program ran. The pinned external arm_clear_state selected
Supervisor mode but left IRQ/FIQ masks clear. An authored helper within the private
ARM translation unit now applies both masks after the original reset routine;
constructor and later CPU-reset paths use it. Original external function bodies
and the qualified earlier probe remain preserved. The current context can advance
chip timers while held, then run from its reset vector despite pending interrupts.

Primary reset reference: ARM7TDMI Technical Reference Manual, section2.10 Reset.
https://documentation-service.arm.com/static/5e8e1323fd977155116a3129
The specified reset state uses Supervisor mode with IRQ and FIQ masked. This
specific correction does not establish complete ARM instruction/cycle conformance.
