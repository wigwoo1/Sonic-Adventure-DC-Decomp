Verified change

The complete original recording_update and pad_scan now link into the private
native frame runtime. They use the existing input, RZ math, camera, heap, task,
clock and renderer owners. No dummy recorder or forced unresolved link is used.
The old helper-only build, all prior source/proofs and retail inputs are retained.

The authored recording boundary replaces fixed Dreamcast addresses with one
typed native sample array. The original 12-byte little-endian sample layout is
asserted at compile time. Recording retains its inclusive limit, six filenames,
sentinel and historical double cursor increment. Playback supports the original
inclusive 0x180000-byte limit plus its last 12-byte sample, but can read only the
bytes actually loaded. Malformed/truncated/no-sentinel recordings are rejected.
Whole samples after an aligned sentinel are preserved; the original recorder
still ends on the first sentinel. Invalid cursors stop native playback, report a
sticky error and request QUIT rather than reading unrelated process memory.

Native saves write and flush a temporary file in a configured existing Unicode
directory, then replace the selected recording atomically. Failure preserves an
existing file and removes the temporary. Only the original recorder's six export
names are accepted. This is a recorder-specific replacement, not an implementation
of every debug host_save_file caller. The original ignores the save return, so
the host must inspect jp_recording_status. An outstanding error prevents further
buffer operations until explicitly cleared. Debug output uses OutputDebugStringW
and maps the cursor back to its original guest address; no 64-bit pointer truncation.

Original get_character and set_character_number bodies use one character_current
field. The original stage_end body is compiled as a local constant-QUIT inline
specialization for the recorder's sole call argument. Its real stage_end_kind=6
effect is retained and compared against original execution. No clear-event stub
exists: that unneeded branch is removed by constant propagation, confirmed in
LLVM output. The rest of the stage engine is not integrated. Later stage work
must adopt this same state owner rather than introduce another end/character field.
set_character_number is the original number-only setter; the full character
resource/lives/chao transition set_character is still unported.

Remaining integration

The presenter's frame-wait peripheral service is still a diagnostic trace.
It must call the real input owner, using a validated HWND supplied by the actual
window owner. Do not cast an opaque jp_window pointer to HWND. Native exit
lifecycle and the full original logo_step/boot path remain unverified. Full
split-frame control, scene/event handling, audio and gameplay remain open.

Use either the standalone authored recording DLL or the integrated frame DLL,
never both as independent recording owners in the same game process. The same
restriction applies to standalone versus integrated input providers.
