What the initializer actually does
The player constructor stores 0x8c0b3a2e in its newly allocated child's callback
field. The exact entry was absent from the original exported function index;
Ghidra established it explicitly in a read-only session using the stored pointer.
No nearby function was assumed to own it, and project changes were discarded.

The initializer installs pointers 0x8c0b3b1a, 0x8c0b3f2c and 0x8c0b3afc in the
child task, resets selected child-actor fields, and searches five original table
records with character IDs [2,7,0,3,5] and stride0xd8. The query reads player0's
actor byte at offset9. An absent player0 pointer tail-calls the original unsigned
16-bit global getter. These are character IDs; an early working description of
the query as a stage query was corrected from the original instructions.

The initializer does not call the movement owner. Assigned subsequent callbacks
are stored but have not been executed or qualified in this milestone. The real
retail scheduler order and movement/collision startup requirements remain open.

Build and dependency recovery
The complete 275-source initializer/query proposal compiled, but its first
execution stopped at an unrouted original dependency 0x8c042dc4. Its source,
reports and compiled artifacts are preserved. Qualification applies to the
276-source dependency-connected build, not that earlier incomplete proposal.

The final build adds exact original bodies for the already recovered constant
zero routine0x8c042dc4 and global getter0x8c04f698. These six instruction rows
are canonical reuse with zero duplicate routine credit. Their uniform adapter
names differ from historical registered names, so exact-name DLL inventory
conservatively excludes those aliases. No query result was supplied by a test.

Both builds compile. The final 276-source build and a separate strict unbounded
-Wall -Wextra -Werror check pass. All74emitted original instruction encodings
match the local Rev A executable. Only the two actual initializer JSR returns
are added to return membership. Existing CPU/FPU/bus/ABI behavior, guest limits
and prior source/proof files remain unchanged; no new guest wait bound is added.

Remaining limits
Ordinary-entry software qualification does not cover arbitrary externally
supplied intermediate PCs, asynchronous register corruption, physical hardware,
full boot, subsequent callbacks or every retail scheduler/collision producer.
The renderer, movement owner/routing and broader response contracts retain
their prior gaps. PC60/120/240FPS8K, Android, stereoscopic3DS, N64/PS1, SUPIR and
texture/display settings remain planned. TextureOff must disable sampling and
use vertex/material colours. The goal remains active.
