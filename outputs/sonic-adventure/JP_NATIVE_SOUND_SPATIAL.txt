What changed
The native sound graph now supplies matrix_calc_point and njUnitVector, and
links the original Japanese qsound_place against them. The point transform
reuses the already qualified njCalcPoint(NULL,point,point) path in the actual
frame DLL. It includes translation and uses that DLL's one live Ninja matrix;
there is no separate sound matrix or copy of the renderer's matrix owner.

Vector normalization follows the original FIPR/FSRRA/multiply sequence and
returns squared length times reciprocal square root, as the shipped routine
does. It preserves original zero/nonfinite outcomes rather than inventing a
fallback direction. The existing pinned numerical model and frame DLL scalar
providers supply the fixed toward-zero/DN1 value policy. This is value
compatibility, not a new hardware measurement or FPSCR/register emulator.

The original qsound_place copies the shared sound slot position, transforms it,
sets Y to zero, normalizes, then converts the horizontal coordinate to a QSound
position. Only its host-sensitive arithmetic is adapted: explicit RZ add/mul
replace native default rounding, and defined FTRC plus unsigned shift semantics
replace undefined C conversion/overflow cases. Its source and adaptations are
hashed separately. The same real slot table remains owned by the sound module.
Fixture entry points only write/read test input and call the actual function;
they do not supply an invented camera, player, request queue or stream service.

FIPR/FTRV/FSRRA use the same previously pinned numerical approximation model in
the native adapter and instruction service. Therefore their opcode comparisons
prove call/control-flow/value integration relative to that model, rather than
independently proving its hardware accuracy. The independent geometry/scalar
cases provide additional evidence, not a substitute hardware claim.

Reproduction
Use bundled Python with -B from this workspace. Run build_native_sound_spatial.py
with --workspace ., --upstream the pinned reshaped-sonic-adventure-review,
--baseline work/sonic-adventure/jp-native-qsound-v5, and --output a NEW private
work/sonic-adventure directory. Then run verify_native_sound_spatial.py with
--workspace ., --upstream that checkout, --build the new directory, --binary
the extracted matching Japanese 1ST_READ.BIN and --output a NEW test directory.
The pinned work/sonic-adventure/build/sh4_vector_numeric.dll is required too.
The verifier compiles a thin result-bit probe into its own private directory.
Rerun the existing QSound, timing, owner, exit, save and startup suites, and
audit_native_sound_after_spatial.py. package_native_sound_spatial.py binds their
terminal reports and preserves the prior qualification. Never overwrite proofs.

The first verifier stopped because its explicit vector instruction service had
not been supplied; it was corrected to use the existing pinned service. The v1
native build itself passed spatial/audio/exit tests, but omitted 29 inherited
nested audit-source files, so the frozen save verifier could not inspect all
inputs. The builder now copies every inherited generated input by its hash.
v2 rebuilt cleanly and the current checks use it. Previous variants, the original
v1 builder snapshot and logs are preserved; failed attempts are not relabeled.
