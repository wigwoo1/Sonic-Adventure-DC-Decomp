The symbol audit found stage_end_kind already owned privately by the genuine
recorder implementation. A fresh derived recorder source changes only that

state declarations are unchanged. The new stage_begin and old recorder now use
one field. Runtime checks observe stage reset through the existing recorder
getter as well as the new state view. No recorder success substitute is added.

The original progress_init first clears 96 bytes from a 16-byte scratch array,
depending on the next array's placement in Dreamcast BSS. Later in the same
function it clears all 512 bytes of that next array. The native version bounds
the first clear to its actual 16-byte object; the later original clear remains.
Complete post-call state matches the Japanese machine code. This avoids an
out-of-bounds native C write without requiring adjacent global allocation.
Intermediate store order across those two clears is not an observation API.

boot_finish also needs fill_bytes, originally a short SH-4 assembly routine.
The new native recovery writes value's low byte backward for positive counts.
The original requires positive count: zero underflows and can overwrite below
the destination. Native null/nonpositive requests are safe no-ops, an explicit
repair outside that valid original contract. Positive calls still require a
valid caller-owned destination of at least count bytes; there is no size-free
promise that arbitrary pointers can be validated.
