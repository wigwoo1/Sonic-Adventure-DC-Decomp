Native original GDFS over the real Japanese disc-data reader
Qualified 2026-11-05. Whole project approximately 10%; goal active.

What now works
The original SDK filesystem software now runs as compiled Windows code over an
authored GD_DCF interface backed by actual read-only native file I/O. It starts
the virtual drive, reads the primary volume and path table, loads directories,
opens finite file handles, reads/seeks/streams real game files, reports errors,
dispatches completion callbacks, cancels requests, reinitializes and shuts down.
This is a private research library, not a playable game or a new game screen.

Native adaptations
- Derive work and callback arena sizes from native sizeof/offsetof. Native
  handles are 120 bytes here; original serialized directory entries remain
  44 bytes with a 16-byte table header. Guard-page allocations retain real
  pointers above 4 GiB. Legacy console work buffers are not dereferenced.
- Bind the original library interface directly to its compiled table. Omit
  console overlay descriptors and the nonexistent physical DMA chain. Keep
  original software state transitions and the real priority-80 vblank entry.
- Replace truncated pointer casts, bound directory records and total directory
  work, and validate the volume/path table before original initialization.
- Replace firmware settling spins and IRQ-only waits with actual monotonic
  progress deadlines and native I/O cancellation. Retain unfinished resources
  when cleanup fails. The local disk did not exercise a slow OS-I/O timeout;
  that branch is reviewed, not claimed as runtime observed.
- Clamp large public sector requests at EOF before original signed additions.
  Actual INT32_MAX read-count regressions pass without overrun or wrong data.
- Dispatch transfer callbacks after actual copies and original state updates.
  CPU reads do not invent DMA callbacks. Closing/recycling a handle suppresses
  a stale pending transfer callback. Callback delivery does not reproduce the
  Dreamcast's exact physical interrupt timing.
- Stage directory loads so failed or undersized loads preserve prior tables.
  Preserve original handle capacity, case-insensitive lookup and sector rules.

Caller contract
Configure the local track first; initialize the real shared clock/wait service
before GDFS startup. The original library expects first FAD 45150. Supported
tracks are raw Mode1/2352 and cooked/2048. Chunk and deadline values are bounded.
The single creating thread owns handles and service calls. Do not independently
request, replace or close the underlying native media while GDFS owns it.
SDK read buffers need sector-rounded capacity; asynchronous DMA and streaming
entry points retain 32-byte alignment rules. Keep destination storage alive
until completion or successful stop/close/reinit/shutdown. Callbacks may query
and queue nonblocking I/O. Recursive server calls do nothing; blocking I/O and
lifecycle changes are rejected when they could reenter callback processing.

Unsupported services remain explicit
CD-DA, TOC and subcode/audio support are unfinished and do not return fake
success. A mounted data image has no physical tray/seek timing. KallistiOS's
published drive-state definitions informed the virtual-data-medium statuses;
no KallistiOS implementation was copied:
https://raw.githubusercontent.com/KallistiOS/KallistiOS/master/kernel/arch/dreamcast/include/dc/syscalls.h

What remains next
The standalone GDFS provider supplies gdFsInit/gdFsChangeDir to the compile-only
sbInitSystem import audit: 13 imports now have five unavailable providers rather
than seven. This does not link or execute that unsafe console-address probe.
The five remaining names are _builtin_set_imask, syHwInit, cache_ram_init,
_BSG_END and syHwInit2. Build a real native parent coordinator using the actual
heap/device/input/RTC/GDFS owners and native configuration; console pointers,
interrupt masks and hardware writes must not enter PC execution.

Integrate GDFS cleanup authority into the qualified native exit graph before
parent execution. Close/drain GDFS before RTC, device quiescence or shared wait
shutdown; all consumers must finish before the final SDK heap. Preserve partial
failure rollback and one-owner/token rules. No new graphical build was run for
this filesystem-only change. Previous qualified boot/renderer DLLs are unchanged.
