The four complete pinned modules adx_inis.c, adx_tlk.c, adx_tlk2.c and adx_tsvr.c
now compile and link into the existing native sound module. All54 source-defined
functions are retained, plus the original syTmrDiffCount from sh4tmr.c. This

original game's stream task. Its remaining data import and fixed-address work
setup still need integration before that task can run safely.

One lifetime and clock
The actual eight ADXT records remain the player registry. Native APIs allocate
guarded,32-byte-aligned music/voice work, and free it only after the actual player
has retired. Initialization preserves live lower file streams, renderers, joints
and error callbacks. It neither reinitializes shared pools nor registers another
vblank callback. Explicit parent shutdown rejects an active ADXT owner. Global
shutdown retires ADXT first, followed by ADXF, ADXSTM, RNA, SDK/G2/AICA and GDFS.
Rejected cancellation/cleanup retains its player/work for creator-thread retry.
An ADXT-owned error callback is restored to the previous callback after cleanup;
a subsequent external registration is preserved.

The existing AICA frame counter schedules one complete original ADXT server step
per735 frames at44100Hz, or60 logical steps per second. Polls without new audio
time do not accelerate it. Each SDK service catches up at most eight steps and
retains outstanding work. While ADXT is active, its complete original server
replaces the individual automatic lower servers, avoiding duplicate execution.
The existing sound clock/output worker remains the only real-time output owner.
Rendering at60/120/240FPS is separate from this audio cadence; whole-game FPS
behaviour is not established by these audio tests.

Native repairs
- Work alignment uses uintptr_t; invalid channels, undersized/overflowing work
  and nonpositive server frequencies are guarded. Partial constructors reserve
  the real slot and clean up nullable subcomponents without dereferencing NULL.
- File/AFS/memory-start failures balance the original critical-section lock.
  Failed archive lookups are checked before opening a range. Stops drain actual
  deferred SDK transfers before interrupt-masked cleanup and preserve a lower
  stream when cancellation/close fails. No transfer or ARM acknowledgement is
  fabricated.
- Preparation uses actual renderer room rather than the original constant-zero
  ADXRNA_GetNumRoom stub. Finished short streams can begin once data is ready.
- A finite decoded tail is padded once through the actual output joints to the
  renderer's16-sample transfer unit. At most15 zero samples are appended. Retail
  headers/sample totals remain unchanged; final ADXT_GetTime returns that total.
- Original RNA wrap mirrors are four-byte synchronous CPU writes through the
  existing real SDK/G2 path. They no longer report short streaming-DMA warnings
  or silently change the global transfer mode. Actual streaming blocks retain
  the selected CPU/DMA mode, bounds/alignment checks and completion mechanism.

Reproduce locally
Use build_native_adxt.py with --workspace, --upstream, --baseline, --inputs and
--output. The baseline is the qualified ADXF build; inputs are the privately
prepared genuine ADXT matching includes. The build uses the preserved compiler
commands, including the RNA module's required include paths/warning adaptation.
Use fresh private output directories. Run verify_native_adxt.py with --workspace,
--build, --track and --output. The Japanese disc and firmware must be supplied
locally. Public source contains the authored adapters/workflow and proof hashes;
external game/SDK source, matching text includes, binaries and audio stay private.
