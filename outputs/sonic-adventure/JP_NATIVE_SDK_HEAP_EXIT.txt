What changed
The actual SDK heap is now included in the qualified startup/exit composition.
The test caller creates 1MiB+32 of real backing before the complete native Ninja
initializer, preserving an original full 1MiB usable arena with safe alignment.
Original main buffers/vertex/font/text setup, display reset, boot_init and logo
continue through their actual providers. A real C test consumer holds 256 SDK
bytes across the original boot/logo and validates/frees them when the original
task-destruction loop invokes its native C destructor. This is a controlled
test task, not a claim that all game/SDK allocations are already routed here.

The general exit service claims the SDK heap once and closes it after all other
selected consumers and device resources. It drains/quiesces the graphics device
first, destroys tasks and releases their assets, finishes device/window/GPU
cleanup, then finalizes the SDK arena. SDK allocation/free/stat remain usable
while consumers retire. Ordinary syMallocFinish/native shutdown cannot close a
delegated arena. Outstanding SDK allocations preserve the arena and its exit
authority for a retry, without rerunning completed task destructors.

A 64-bit creator-thread token records terminal heap cleanup authority. Wrong
full-width tokens, duplicate claims and foreign lifecycle calls are rejected.
An uncommitted heap claim can be cancelled before its first finish attempt;
cancelled tokens are never recycled. A failed later device claim cancels the
heap claim, so a rejected exit bind does not strand either owner. If rollback
itself unexpectedly fails, the exit service retains the actual heap token as
recoverable cleanup state rather than forgetting ownership. Normal rollback
paths are exercised with genuine missing/already-claimed native devices.
The token and creator-thread restriction persist after completed final close;
ordinary reinitialization does not imply a same-process game restart.

Existing exit structures and classic masks remain compatible: ALL=16383 and
WITH_DEVICE=18422 keep their meanings. SDK_HEAP=32768 adds the SDK owner.
WITH_DEVICE_SDK_HEAP=51190 selects it with the delegated device and other classic
owners, using NULL raw GPU/window handles. Native CRT, task, texture/frame and
GPU allocators remain separate. No global malloc/free/realloc/calloc override
was introduced. Other original SDK modules still need deliberate typed scoped
allocation bindings when they are integrated.

Scope and next bootstrap work
This is an integration of actual native factories and cleanup through the
existing Python test caller. It does not yet execute the complete original
sbInitSystem or main system_boot_init. Hardware/input/RTC/GDFS bootstrap and
sound remain required. The original console-address bootstrap probe is still
never linked/executed. Its 13-import frontier has nine unavailable exports:
_builtin_set_imask, syHwInit, cache_ram_init, _BSG_END, syHwInit2,
pdInitPeripheral, syRtcInit, gdFsInit and gdFsChangeDir. These are this one
bootstrap's dependencies, not the whole game's remaining routine count.

Next replace the remaining console-only bootstrap assumptions with real host
platform/input/time/file behavior and put the verified creation/rollback order
into the native parent coordinator. The heap must use actual bounded backing,
not MEMORY_END/_BSG_END addresses. Preserve one final-close authority and the
current consumer-before-arena cleanup. Do not invent successful hardware,
cache, filesystem or audio substitutes. cache.src's three RAM-mode entries
really return immediately; verify original instructions before porting that
specific genuine behavior. Android/3DS and presentation enhancements remain
later full-project work, not completed by these memory tests.
