Observed material behavior
All three original node lists are [1,3,6,9,11,13,15,18,20,22,25,36,38], followed
by ffffffff. Each helper copies its list to the original stack frame, follows
entity+24c's selected object table, and visits every material in each selected
model. It writes a zero-extended ID at material+0c and ORs 00400000 into
material+10. Other material bytes and all unselected materials remain intact.
The variable helper reads appearance+192 as an unsigned byte. Values 0..3
select IDs 217,218,219,220 from the original table; any larger byte selects 217.
The other helpers use IDs 158 and 161 respectively. These are data-field
updates; no texture images or visible pixels are generated by these tests.

Object setup calls the palette variant if appearance bit 40 is set, then
chooses a tail variant by priority 04 over 08. It restores its stack/saved
registers and caller PR before its tail branch. The outer initializer later
selects its own tail by priority 40 over 04 over 08. Tests distinguish these
nested choices and preserve the original order and raw wide-FMOV effects.

Allocation-failure finding and guard
The original clone can leave a parent whose child failed to copy. A short tree
then leaves table slot 34 unset, while the original model selector tries to
store through that missing node at 0c905572. The valid-destination selector is
reused unchanged. New support source/sa_overlay_selector_guard.c handles an
invalid destination by executing the original 21-instruction prefix, then
returning -3 before the unsupported FMOV store. It preserves original reached
registers and FPU changes and reports PC 0c905572. It does not invent successful
initialization, repair the partial tree or deliver a hardware exception.

Root-copy failure still stops in the existing root walker at 0c9044f2, after
its original output-table write. PR=1 stops at object setup's FLDI0 0c904d5e.
Small heap capacities exercise root failure, missing descendants and actual
native heap release when a copied child's model allocation fails. These cases
are expected partial executions, not completed initialized objects.

Verification design
The focused material verifier executes unchanged original instructions and
compares all 16 MiB RAM, integer registers, SR, PR, PC and FPU state. Its
separate semantic check applies only the documented ID/OR updates and verifies
all neighboring/unselected materials. All 256 appearance bytes and all eight
FR/SZ/PR combinations are covered for the variable variant. Zero, one and
multiple materials, unsigned clamping, physical/cached/uncached entity aliases
and empty lists are checked. Empty-list cases modify data only; instruction
bytes are unchanged. Combined tests use unchanged shipped root/list data.

The selector-guard verifier compares both the unchanged normal selector and
its exact partial prefix against original instructions across all eight modes,
representative flag priorities and valid/invalid destination classes. Invalid
cases verify that no RAM write occurs before the guard.

The combined verifier executes the original whole initializer, recursive clone,
walks, material variants, selector, heap/free/copy and reset helpers. It compares
full RAM/CPU/FPU and ordered boundary states, including a digest of every heap
byte at every boundary. Independent checks verify the allocated object tree,
seven 39-node preorder tables, type-7/type-0 alias, all material changes before
selection, selected model/scale and preserved data, resets, copies, masks and
the exact nested and outer variant order. All eight shipped types, four legal
setup transfer modes, representative model flags and appearance combinations,
explicit missing/error services, PR guards and bounded heap failure cases are
included. This combines previously isolated recovered bodies in one native path.
