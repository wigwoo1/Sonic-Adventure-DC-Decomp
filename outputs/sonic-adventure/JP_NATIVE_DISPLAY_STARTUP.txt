What changed
The original syCblCheckCable body now compiles unchanged into the shared frame
owner. Its lower-level Dreamcast hardware-pin read is replaced with a real
Windows current-display query. Successful PC queries choose the original
progressive VGA-compatible path; this does not identify the physical cable
connected to the user's monitor. An unavailable query returns the SDK reserved
profile rather than inventing a connected display. Future native startup must
check actual resource initialization; a decoded profile alone proves no GPU.

jp_display_query returns current physical pixel dimensions, pixel depth,
display flags and a driver-reported refresh value, with explicit validity when
the latter is more than one. It never changes the desktop mode. This value is
not measured game/render timing or proof of 60/120/240 FPS support. Physical
monitor dimensions are separate from original game logical dimensions and
future selectable render resolution/aspect ratio.
Primary Windows API reference:
https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumdisplaysettingsw

The three actual original main.c definitions, cable_mode, dat_8c78b4d8 and
dat_8c78b4dc, are restored once in the shared frame DLL. Their original four-byte
types are preserved. The builder checks that no previous linked object defines
them, checks pinned source against Git, and exports genuine data imports.
No sbInitSystem or sound initializer placeholder is added.
