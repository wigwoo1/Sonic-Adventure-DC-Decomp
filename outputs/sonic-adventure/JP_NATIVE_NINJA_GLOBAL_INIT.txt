What changed
The entire njInitGlobal body and the complete njLightSystemInit source now run
with the real shared frame/queue/context/video state. All existing imports
resolved in the current frame owner on reinspection; no new higher layer or
circular DLL dependency was necessary. Earlier handoff suggestions about split
owners were superseded by this actual symbol inventory.

Six missing original objects now have one typed owner: the 16-Float easy-light
source, 32-Float destination, light material, light control, light queue and
motion callback. The five assembly-reserved light blocks keep 32-byte alignment.
The material is 52 bytes; native control is 264 because it contains 32 pointers;
the queue remains 132 because its entries are integer indices. The callback is
a native pointer. Original scalar and serialized widths are not widened.
The builder checks existing linked definitions before introducing any object.

The original global body is unchanged except for its private entry name. Its
upstream GCC repair writes 16 source and 32 destination Floats explicitly,
instead of overrunning a 16-Float object. The subsequent integer marker 3 keeps
its exact bits in the destination's first word. The original light body is
unchanged. Source/header bytes are checked against pinned commit
25a3d3154dbe657325e97dbe8c5291086f6af5c0 and remain untouched.

A native entry guard validates ready video/queue/frame owners and rejects
active producers, recorded work or submitted frames before writing global state.
Logical dimensions come from the actual native video snapshot. The guard selects
the real initial context slot, which the existing context guards require, then
runs the complete original initializer. The original context headers, render
defaults, clipping, counters, light state, sprite setup and culling operations
execute through actual providers. The SDK void entry reports failure through
jp_ninja_global_status; it does not manufacture successful initialization.

One game thread and fresh/quiescent startup are preconditions. Native wait/vsync
callbacks belong to their existing owner; callers keep them quiescent during
this setup. The original opaque vsync_handle reset does not by itself unregister
a host callback. The full native device/system coordinator must preserve that
lifecycle and error handling before this can serve general system re-entry.
