Native main bootstrap: card/font lifetime and global exit qualification
2026-11-06; whole project approximately 10% of weighted milestones.

Status: scoped native lifecycle VERIFIED. This is an incomplete research
integration, with no playable PC executable. Japanese source matching and GCC
baselines remain preserved. Full gameplay, English localization, settings,
Android, stereoscopic 3DS and VMU mini-game emulation remain unfinished.

What changed

The existing System bootstrap owner now acquires real card and original-font
cleanup claims after the complete original system_boot_init constructor. It
uses the SAME existing early-exit callback; there is no second registration.
MainBoot delegates those resources to System instead of keeping parallel
shutdown authority. The dependency direction remains MainBoot -> System ->
Exit -> Frames. Exit does not import MainBoot or System; Frames imports only
Windows system libraries. Earlier qualified source and proof hashes are intact.

Claims identify actual providers in Frames. Card claims inspect genuine card
work and native fiber state; font claims inspect the original print parameter,
descriptor and real texture payload. No replacement game state or successful
initializer is fabricated. Tokens increase across ordinary restart, belong to
their creator thread, and cannot be cancelled after terminal shutdown begins.
Independent legacy destruction/replacement is rejected while a claim owns a
provider. Reentry from active card callbacks/fibers and print packets is checked
BEFORE global exit counters, terminal flags or bootstrap.started are changed.

Ordinary/early System cleanup drains card, timed sound, GDFS, RTC, input and
device, then retires the font and SDK heap. Final Exit adopts the same card/font
tokens after its other claims succeed. It drains card before sound/core,
quiesces the device, retires captured frame storage, and closes font before
whole textures and the SDK heap. Legacy resource masks keep their meanings;
CARD=1048576 and PRINT=2097152 must be explicitly covered by final binding.
Rejected masks and later device claims preserve the original bootstrap owner.

Timeout and failure behavior

Actual queued saves are serviced through original buExecServer/fibers. A short
lower-level deadline preserves the claim and dependent core resources. A real
Windows file-sharing denial also reaches the global deadline: the original SDK
keeps retrying/scanning free blocks, so cleanup must retain ownership. Tests
keep the denial in place until the actual original completion reports failure,
then retry cleanup. The entire previous VMU image stays byte-identical. No
successful save is manufactured. A failing sticky font release similarly
retains the font and dependent SDK heap until the caller corrects the error.
The font observer reads actual state without clearing a sticky texture error.

VMU store and LCD endpoints are borrowed, not silently adopted by System/Exit.
They remain caller-owned until explicitly closed, and their real image locks
can then be reacquired. Tests use fresh disposable images, never user saves.
An early exit cannot close a device while a caller-owned captured frame is
live: it reports the real block, retains the font obligation and leaves captured
font bytes readable until the caller releases that frame and retries. Final
exit intentionally ends selected frame-storage lifetimes before font teardown.
