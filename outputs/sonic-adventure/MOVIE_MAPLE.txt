Verification and build
movie_maple.dll compiles from 167 sources. All 80 original-instruction/native
comparisons and 748 independent assertions pass. Full CPU, RAM, FPU, special
registers, software peripheral storage, sample cursors and ordered ordinary
boundaries are compared. The previously qualified independent full-clear
decoder/probe remains unchanged. The actual early caller executes 2,097,152
clear-helper stores, clearing the complete eight-MiB software VRAM image.
Long clear traces retain the earlier documented compression/fingerprint limits;
this is not a new claim that every large trace was stored uncompressed.

Host results: 67 normal returns, 10 expected invalid-memory stops (-3), two
actual unrecovered-callee stops (-2), and one expected privilege stop (-4).
These negative statuses are intentional test outcomes, not ignored failures.
All fourteen integrated routine coverage records have no missing rows/outcomes.
The eleven new registrations exclude the three canonical reused helpers.

The independent record oracle checks all 24 blank records and both 24-entry
buffer tables. Original library flag bytes at 8c672498 are explicit test inputs;
they are not measurements of physical controller presence. Revision-zero/one
and eleven profiles exercise the original flag masks. The forward copy uses
the special R0=count, R1=destination, R2=source convention, preserves R2/R3/R4,
and deliberately propagates forward overlapping writes. It is not memmove.
Signed zero/negative fill counts, tails, boundaries and partial faults are tested.

The command oracle checks the complete context and command buffer, both word
orders, both payloads, both buffer banks, busy rejection, final unit, command
byte truncation, serial wrap and padding conditions. Serial is at context+4064;
wrap skips zero. The parent takes buffer pointers in R4 and R6, independently
checked for 32-byte upward alignment and the original address alias. Ordinary
ABI assumptions about R5 would miss the second alignment path.

Actual startup and remaining boundaries
The precision-zero early caller 8c010180 uses original producers to establish
heap 8c88ef1c, device context 8c7ac7a0 and controller context 8c8a72b8. It clears
VRAM and completes controller/command setup, then stops at real RTC reader
8c10be78. Its 46-row read-only export is retained as the next research frontier;
it is not connected or granted routine credit. Earlier caller/driver parents
remain partial outside the newly closed controller bodies.

The revision-eleven profile is the prior explicit raw hardware observation,
supported by pinned Flycast source in MOVIE_REVISION.txt. The default platform
has not silently changed. A revision-zero control still reaches unchanged
callback 8c000000. No constructor, firmware, callback, input reply or clock
result is substituted. Precision-one is not supported throughout startup.

No physical controller reply, DMA execution, hardware interrupt, actual timing,
visible pixels, natural complete boot or playable port is established here.
60/120/240 FPS, 8K, Android, stereoscopic 3DS, N64/PS1 and SUPIR/texture/display
settings remain pending. Texture Off remains planned as untextured vertex color.
