What changed

The SAME qualified motion/model data owner now transfers cleanup authority to
the existing System bootstrap callback and final Exit. There is no second motion
pack, System instance or cleanup registration. An explicit new resource bit,
JP_EXIT_MOTIONS (16777216), leaves previous masks unchanged. Final resource masks
must include it whenever System owns motions.

System starts motions only after the real parent is ready. An independent owner
may instead be adopted under the existing main-initialization guard; preclaimed
owners reject before parent mutation. Starting cannot steal an independent owner.
An internally acquired guard is released on success or pre-acquisition failure;
an outer caller's guard remains the caller's responsibility. Original game_init
callbacks cannot start/adopt the owner while construction is in progress.

One 32-byte capability snapshot tracks the exact token and terminal/closing/
finished state in the actual motion owner. Adoption and final handoff permit live
consumer views: transferring responsibility does not destroy their data. Strict
retirement additionally requires zero live views. Independent shutdown/restart
cannot bypass the delegated token. Creator-thread checks also survive a delegated
close until ordinary cancellation or permanent terminal finalization.

System, MainBoot, game_init and global Exit check active views BEFORE changing
parent ownership, cleanup counters or irreversible bootstrap flags. A failed
preflight leaves view bytes, card/audio/History/queue/GDFS parents and profile
usable. Release the actual views and retry. This is explicit consumer retirement;
future tasks, texture bindings and retained render jobs still must acquire/hold/
release their own real views. Automatic acquisition by those users is not done.

When motions are owned, ordinary MainBoot cleanup routes through the same System
shutdown before its older card-first path. System/Exit retire motion data first,
then drain card callbacks, then queue, History, sound and the remaining actual
core. A card callback cannot create a late view between preflight and retirement.
MainBoot clears only card/print flags actually owned by that System. The previous
path without motion ownership retains its existing behavior.

If later History persistence fails, the motion data may already be closed, but
its exact ordinary capability remains retained along with the necessary real
parents. Correct the save failure and retry; it is not closed twice. Complete
ordinary cleanup cancels the token and allows a fresh original game_init session.
Early/final global Exit instead makes the same capability terminal; cancellation
and restart then reject. An ordinary partial close can also finish globally.
