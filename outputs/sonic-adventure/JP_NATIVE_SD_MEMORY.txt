What is recovered
Thirteen pinned original SDK modules compile/link privately with fourteen original
function bodies unchanged. They include block-table initialization, allocation,
release, parameters/status/source/callback setters, completion and error/debug
support. A diagnostic fixture seeds an actual typed work record and 64-slot pool;
it does not export sdLibInit, sdDrvInit, sound_system_init or G2/DMA success helpers.
The production SDK bootstrap and its fixed-address/pointer alignment still need
adaptation. A test fixture creating work is not their replacement implementation.

Native-only layout adaptation
The public opaque SDS_MEM_BLK buffer is32bytes on Dreamcast, while the actual
pointer-containing native sd_memblk is48bytes. A private header overlay provides
the corresponding pointer-aligned span. Every original record field and function
body remains unchanged; serialized command packets and sound offsets are not
widened. Native size_t uses the existing host adapter. GCC varargs are enabled
only after SDK hardware declarations have been parsed without SH-4 assembly.
The SDK's legacy vsprintf declaration links to the actual installed Microsoft
legacy_stdio_definitions compatibility library; no formatter-success stub is used.

All native source compiles/links with -Wall -Wextra -Werror and zero diagnostics.
The first compile correctly rejected SH-4 inline assembly because GCC was enabled
too early; the second compiled but exposed the real legacy CRT link dependency.
Both failure logs and their earlier source versions are retained. Original checkout
source/header hashes match pinned revision25a3d3154dbe657325e97dbe8c5291086f6af5c0.

Driver-loader alias result
sdMemBlkDestroy marks a pool slot unused and decrements the live count. It retains
the data pointer, size, callback/context, status and other descriptor fields.
The original completion/setter routines can still access that released slot.
The next allocation selects that same slot and resets its fields at reallocation.
All these behaviors match complete original instructions and actual native C.

This explains the alias in sound_init_driver's final sdDrvInit(block) after
sdMemBlkDestroy(block). The retained descriptor initially still names the driver
header; an internal allocation can subsequently reuse the same slot. It must not
be ported as a heap free followed by a dereference. Complete repeated sdDrvInit,
its actual transfers and callback ordering have not yet been executed through
the original SDK; the pool result proves these primitives, not the entire loader.
