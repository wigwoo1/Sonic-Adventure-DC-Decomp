Why an explicit check

The initial nonlocal-jump draft failed in native Windows stack unwinding. The
SDK's SH-4 setjmp header was incompatible with Windows; host CRT isolation fixed
that header mismatch but nonlocal unwinding still failed. That approach was
stopped under the user's debugging rule. The checked-return adaptation uses no
setjmp/longjmp. Both failed builds and proof logs remain private and preserved.
JP_NATIVE_MAIN_BOOT_DRAFT.txt retains the historical unqualified notes.

Ownership and failure behavior

The caller configures the existing System owner, creates empty queue/frame/
texture/render prerequisites, registers the actual original 256KB main buffer,
and supplies real VMU store/LCD owners. Borrowed callbacks and these owners must
outlive use. A preexisting ready System, card backend or live texture is rejected
before entering the original parent. No foreign owner is silently adopted.

Cleanup authority over System begins only after the original sbInitSystem has
succeeded. A rejected parent does not close an unrelated System. Acquired
authority remains until successful cleanup and prevents reconfiguration while
cleanup is unfinished. Local shutdown drains actual card fibers with buExit/
buExecServer before closing sound and core System. It then retires the original
font surface. A sticky texture error that blocks the void njExitPrint call is
detected by actual live-surface counts: cleanup returns an error and retains its
font obligation until the caller corrects the error and retries. It never claims
that an unfreed surface retired.

Original display reset expands texture-table metadata from the caller's initial
32 entries to2048. Font retirement is therefore checked as an actual32768-byte
payload/live-surface decrease, not by assuming total metadata bytes never change.
VMU .lock sidecar files intentionally persist. Exclusive OS handles provide the
lock; successful image reopening proves release. User save images are not used.
