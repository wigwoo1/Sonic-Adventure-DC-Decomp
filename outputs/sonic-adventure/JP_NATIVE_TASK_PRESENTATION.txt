What changed

The complete presentation-aware original task source now links and executes
beside genuine present_run, present_draw, present_forget, present_record and
present_untimed. Actual task allocation, stepping, child calls, drawing and
destruction use the same heap, matrix, texture, context and frame owners.
Real collision/event cleanup functions and the already qualified replay lifetime
guard are retained. The documented 64-bit heap split adaptation and five GCC
presentation hooks remain enabled. No task lifecycle success stubs are added.

Original camera/player state declarations now own their actual records. The
private lifecycle test helpers control these records but no longer define
replacement globals. The three Ninja accounting counters use the existing real
renderer owner; three vsync fields use the original SDK declarations. The
original presentation prefix owns split/redraw/later-draw state. Symbol audits
verify a single shared definition for each selected task/state/clock service.

The unchanged clock and SDK count objects moved into the shared frame DLL.
Presenter clock exports forward to those exact functions. Tests verify identical
function addresses, not merely similar results. Private header overlays import
the actual counters/clock from that owner without changing original headers.
There is no circular DLL import and no second clock accumulation state.

Unchanged original logo_start now imports this complete task/heap owner. Its
diagnostic accessors forward there too; the logo DLL contains no additional task
pool or heap arena. Its original cover setter/getter remain together. Existing
startup error checks still apply because the original function returns void.

Recording and original behavior

Actual retained draws, sprite animation copies, flat vertices, task marks and
callback records are handled by the original selected presentation functions.
An optional authored observer receives diagnostics; it never substitutes for the
real recording or timing functions. With observers disabled, original recording
still runs. Two notification calls instrument the original record/untimed entry
points. The native pointer-hash/timer boundaries and replay deletion guard retain
their earlier qualifications. Other selected function bodies remain unchanged.

Original task destruction retags retained records as resource-released when a
destructor may release textures. It preserves list counts; it does not delete
those entries. Tests check all six actual logo records receive that tag. The
original middle wide anchor is an offset of zero, not screen coordinate 320.

the one authored passive-observer member. It contains no game/SDK function,
