Original game randomness and direct SDK/font surfaces

Whole-project estimate: about 10%, weighted milestones. Goal active.
Japanese matching/GCC source baselines are verified. Full native gameplay,
English, enhancements and later platforms are unfinished. No playable EXE.

What changed

The genuine SDK rand, srand and _rnext state now link into the actual shared
native frame owner. The original unsigned 32-bit LCG state/seed behavior and
15-bit output mask are preserved. These are the game's own symbols and state,
not Windows CRT aliases. Windows x64's 32-bit unsigned long is asserted at
compile time; another platform must explicitly retain this game ABI.

The complete original array_shuffle/memory_swap game family also runs there.
Its FLOAT/FMUL/FMUL/FTRC choice of record is routed through authored integer
RZ/DN1 numerical boundaries, with no host floating arithmetic/conversions in
the adapted shuffle or numerical object. The two separate multiply roundings
are retained, including large counts that are not exactly binary32 integers.
Zero-byte records still consume count-1 random draws. Native invalid-pointer,
negative-size/count and overflowing extent inputs reject before touching the
array or consuming randomness. The valid original caller owns the full array.

A single direct SDK surface is added inside the same texture owner, sharing
its nonrecycled resource-ID generator and frame retention. This is needed for
the original debug font, which lives outside Ninja's regular record table.
Source audit confirms system_boot_init initializes that font before calling
display_reset_full, which initializes the regular record table. The direct
surface now survives genuine njInitTexture, including a zero-record table.
Explicit full host-owner initialization/shutdown retires both resource classes.

Direct bytes participate in live-resource counts, ordinary upload budgets,
SDK table-replacement budgets and simultaneous old/new replacement budgets.
Replacement allocates/copies first. Failure preserves the old descriptor and
resource. Submitted frames retain old direct/regular generations until their
last reference retires. The existing original njSetTextureParam consumes the
direct surface through the same native ownership/ID boundary. No duplicate
texture/frame owner or second resource-ID generator is introduced.

Authentic font data and scope

The original 32,768-byte Japanese built-in font is prepared privately from the
supplied, hash-verified 1ST_READ.BIN. Its symbol and exact SDK split agree on
0x8c67fe90..0x8c687e90; njInitPrint's original pool word at 0x8c622908 points
to it. A generated private include round-trips to the exact original bytes.
The 128x128 twiddled ARGB1555 atlas renders through the real direct surface,
SDK parameter builder, captured frame and D3D11 backbuffer. All 16,384 pixels,
including alpha, equal an independent twiddle/ARGB1555 decoder. One screenshot
is the actual original font atlas on that native test path. Font pixels,
generated include, linked font-data objects and screenshots remain private.

This does not execute genuine njInitPrint, njPrintSize, njCharacter or text
printing yet. Their shared state, store-queue transport and formatting remain
the next integration work. It is an authentic font-atlas rendering test,
not a title/menu/text scene or gameplay screenshot. The source's unbounded
variadic buffer and njPrintF negative-padding bug require explicit bounded
native policies outside the original defined formatting domain.
