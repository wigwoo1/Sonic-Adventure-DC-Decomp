This milestone
The real SDK now downloads the complete audited Japanese MLT bank set and
produces stereo/effect/MIDI commands through its own secondary ring, primary
packer, transfer descriptor and actual completion callback. The actual ARM
driver consumes the lists, generates matching PCM and acknowledges them itself.
These tests no longer copy bank payloads or construct the played command packets
in a diagnostic harness. An independent harness still supplies the API requests
and predicts expected bytes; original game sound_system_init remains unfinished.

Native adaptations and ownership
The qualified previous SDK generated source is an immutable hashed input. New
adaptations make driver-bank locations numeric32-bit offsets with offsetof,
retain native-width host pointers and propagate actual bus/copy/status failures.
The MIDI variadic function's fixed status argument uses native int in its private
header/definition, avoiding C17 va_start on a promoted narrow argument. Its four
wire bytes and data argument rules are tested; other game scalar widths remain
unchanged. An unused matching-only BSS placeholder is omitted from this native
unit. SOURCE macros are scoped between combined translation units.

The real sdSysServer services posted native completions before and after its
original work, at explicit creator-thread safe points. The original SDK gets
its DMA counters before the second service; a subsequent call refreshes them.
Its documented trigger-getter bug still returns the end count. An initial queue
test incorrectly required those observations to remain stale; the corrected
test separately checks unchanged queue state and actual refreshed counters.

jp_sd_download_multi validates complete input spans, record counts, allocations,
payload lengths and alignment before invoking original sdMultiUnitDownload. It
supports negative/no-payload records without treating them as downloads. Its
preflight operates on a proposed local bank table and does not alter live state.
This does not establish rollback after a real mid-transfer device/core failure;
the higher native sound owner still needs to quarantine failed original SDK
bookkeeping and order global cleanup. Raw original SDK exports retain trusted
caller assumptions. A live borrowed AICA core cannot be replaced by the caller.

Builds have no diagnostics with warnings-as-errors; original unused-parameter
warnings alone are disabled. Earlier failed test expectations and all build/
verification variants remain under work/sonic-adventure. No older source/proof
files or hashes were replaced to make this qualification pass.
