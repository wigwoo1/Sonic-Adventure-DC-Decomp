Behavior
The helper takes three vertex-cache pointers in R4/R5/R6 and a six-word signed
UV table in R7. Original callers stage UVs at 8c890304. It computes and caches
each input lighting factor at vertex+1c before orientation rejection. It then
reconstructs camera-space coordinates for projected vertices, uses raw camera
positions for near-flagged vertices, and clips crossing edges at the near plane.
Geometry and lighting factors are interpolated along those camera-space edges.

UVs have a distinct quantization step. For each crossing edge, the code converts
signed integer UV endpoints/differences to float, interpolates with FMAC, then
uses FTRC to truncate back toward zero and stores a 16-bit word. It later reads
that word as signed and scales by 1/256 for output. For example, interpolating
0 toward 256 by about 1/7 produces integer 36 before scaling, rather than keeping
the fractional 36.57 value. Negative values follow the same truncation rule.
The quantized output UV table is at 8c890268; geometry/factors are at 8c890278.
The input UV table remains unchanged in the verified ordinary paths.

Three- or four-vertex packets contain control, projected x/y/reciprocal depth,
scaled U/V, the lighting factor, and a retained eighth queue word. Four-vertex
strip output uses polygon order 0,1,3,2, preserving the UV/factor association.
Original output counters, cursor changes, input cache writes and orientation
global effects remain intact. This helper contains no game-function calls.

Saved-pointer guard and input limits
Wide FMOV fixtures can overwrite a saved vertex-pointer slot in the original
stack frame. At reached instruction 8c611b9a, native/reference paths stop with
host status -3 before a flags load through a pointer outside modeled RAM. This
preserves a clear unsupported-transfer boundary; it is not physical SH-4 fault
or exception-handler emulation. All-near standalone inputs are outside the usual
parent contract and receive original-code comparison evidence only; no valid
polygon-output claim is made for them. Independent UV arithmetic uses bounded
finite inputs whose binary32 interpolation product fits the binary64 calculation
before a single binary32 rounding and integer truncation. It does not prove all
possible floating-point inputs, flags, aliases or overlapping metadata layouts.
