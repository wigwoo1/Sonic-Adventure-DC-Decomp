Observed behavior
The material loop selects the pair for layout 1000000 hex. The routines sum
vertex normals for a face and normalize the result. The normalizer uses FIPR
for squared magnitude, FSRRA for reciprocal root and scalar multiplies to write
the unit vector in place. FR0 also receives squared magnitude times reciprocal
root. Numerical operations use the existing pinned vector/scalar backend.

Lighting is base minus the normalized face normal/light dot product. Material
alpha stays unchanged and RGB is multiplied by this factor, without clamping.
For triangles, the original packet writer supplies the new RGBA on the final
vertex. The first two vertices retain the corresponding queue's colour words.
The tests preserve this provoking-vertex behavior; they do not rewrite every
vertex to a uniform colour. Geometry/control words, input cache-factor retention,
counters, cursors and the selected header slot are preserved. Near crossings
stage vertex pointers and the calculated RGBA block to lower clipper 8c6178c6.
That helper remains an explicit fixture, so its clipped output is not yet proved.

An important original strip-path precondition
At the near-crossing strip branch, original instructions jump to 8c61bc98 before
the ordinary-path initialization of R12/R14/R13. Code at 8c61bca2 then reads a
normal through R14. Arbitrary inherited register values therefore do not form
valid vertex inputs. Forty-eight controlled cases explicitly seed these registers
with valid cache pointers and cover this branch, loop and rejection outcomes.
This is controlled body coverage, not proof that the complete game caller supplies
these values. Ordinary random-register fixtures stop before an unsupported read.
The earlier working hypothesis that this boundary only came from wide FMOV was
incomplete; normal-width strip-crossing inputs can also reach it.
