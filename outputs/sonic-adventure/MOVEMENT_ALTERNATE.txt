What changed
The complete original 075860 response routine is recovered and connected to the
254-source library. All 202 instructions and 20 conditional branch outcomes
execute against original instruction behavior. No original rows or outcomes
are excluded, and no branch is removed because of a decompiler assumption.

Current totals: 1,601 registry entries, 1,598 unique module/address routines,
643 registered routines confirmed linked by exact names in the DLL. Support
and continuation exports do not count as game routines. All 1,600 earlier

Recovered behavior
The owner takes the query through R7, reads its contact count at +28 and the
original 88-byte contact records at 8c6bacf0, and calls actual distance, angle,
dot-product, vector-length and normalization routines. It filters contacts by
angle and the reference vector, tracks the minimum selected distance, and can
limit the query's movement vector at +10. Other branches classify projected
movement without selecting a final response. Separate velocity/state input
records remain unchanged; this owner differs from the earlier 075416 routine.

Original code at 075940 and 075996 includes zero-length checks that Ghidra's
floating-point C draft omitted. Both checks remain and both outcomes execute.
Use the original instruction listing and tested translation as evidence;
the Ghidra draft is a research aid with misleading floating-point types.

Actual stack-history path
The second zero-length outcome is reachable even with separate input buffers.
An original vector-add call first produces -1 or 0 in old stack RAM. The
response then enters normally and allocates its own frame. A contact distance
of 1001 does not replace the initial minimum of 1000, leaving selected index -1.
The subsequent indexed distance read therefore uses the old word at frame+54,
immediately before the distance array at +58. Zero movement has length zero,
which is greater than the negative old word, allowing the second zero-length
branch. A zero old word and nonzero movement provide controls.

No execution frame, return address or callee result is installed. The producer
and response execute their original instructions from normal entries. Initial
RAM inputs and ordinary call arguments are supplied. This demonstrates raw
RAM-history behavior; it does not prove the game's normal object/stack layout
uses this case or justify changing the original behavior.

Test startup fix
The retained Python test runner reached the default import recursion limit
before running tests because preserved stages form a long, finite module chain.
The new reference startup raises the host Python floor to 4096. Guest CPU,
reference execution, bus guards, execution limits and recovered C are unchanged.
The final direct/history/retained checks were rerun successfully. Initial runs
are preserved privately and receive no additional comparison credit.

Preservation and limits
The bridge is exactly the old 253-source bridge plus one entry route, ten real
return sites and ten continuation exports. Original CPU/reference interpreter,
guards, production observer, comparison logic, raw session and ABI remain.
No new source wait bounds are introduced. Of 500 explicit continuation exports,
71 nonlocal routes are qualified and 429 remain unqualified. The new exports
do not independently qualify nonlocal resumes. The new DLL/library are
additional files; all earlier archived builds and proof/source bytes remain.

Successful geometric owner profiles are PR0/SZ0. Selected raw modes, special
values and guards are compared, without asserting physical FPU, exception,
MMU, boot-ROM or GPU delivery. Natural world initialization, complete 0730d8
