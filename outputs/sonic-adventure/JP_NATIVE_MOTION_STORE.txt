What changed

The original loader_read_character_motions C body retains every valid case,
filename and source-area argument. A private compile alias sends its load call
to a real native default-restoration operation over the previously qualified
seven-bank data pack. MOTION_AREA is checked as a source-area tag only: no fixed
Dreamcast address is dereferenced, mapped or used as a Windows destination.

The valid source choices are Sonic 0/Tails 2 -> S_MOT, Amy 5 -> A_MOT, Big 7 ->
B_MOT, E-102 6 -> E_MOT and Knuckles 3 -> K_MOT. Only the original invalid-case
infinite loop is changed, to a checked character error. Unsupported IDs include
Eggman/Tikal in this specific loader; their other event/game data is a separate
scope. The unchecked original void loader is not exported. Future set_character
integration must use the checked result before continuing its own mutations.

This selects motion data, not the game's character_current or texture owners.
It uses the real source-built data verified against the supplied JP disc; it
does not rerun Dreamcast PRS code or pretend a console read succeeded. Reload
copies the target bank's genuine defaults into its actual native records,
including pointers. All nine earlier data objects remain byte-for-byte intact.

One creating game thread owns the controller. Initialization captures pristine
defaults before any pack consumer may mutate them. The caller supplies a byte
budget and a bounded lease capacity. Those limits cover the actual requested
metadata, backup and lease allocations, beyond the already resident module data.
The four-lease test requests exactly 3,881,458 bytes for 3,228,962 bytes of native
record payload plus metadata/leases. These are allocation-request totals, not
measurements of process working set or allocator overhead.

Primary-bank selection restores the requested bank even when switching between
Sonic and Tails, whose file is the same. A live view of the previous or target
primary bank blocks the operation before any data is restored. Only one primary
bank is available for new views. Inactive compiled records are not exposed by
the game-facing API merely because their module addresses still exist.

Shared 1ST_READ model data remains canonical and is not reset on bank selection.
Its views remain usable across primary changes. The two board banks occupy
independent original areas: each can be reset/acquired separately, while views
of the ordinary bank or other board remain live. A board's own views block its
reset. Per-bank generations preserve independent view identities.

Acquire uses the original case-sensitive record name. The returned view has the
actual native pointer, extent, bank/index/kind, generation and a unique token.
Multiple views of one record share its data but have separate lifetime tokens.
The caller keeps a view live through every task, texture binding and retained
draw that uses it. Releasing a view invalidates that logical permission even
though a static module address might remain readable. Raw registry exports are
diagnostics and do not provide an alternative game-facing ownership contract.

Shutdown rejects every live view. Once all views retire, it restores all eight
groups (seven banks plus shared models) before freeing its own allocations.
Fresh sessions use new generations and never reuse old lease tokens. Keep the
data DLL loaded until the owner and all views close. Output structs must be
valid writable caller buffers; outputs overlapping owned payload/storage are
rejected. Windows memory protection is not replaced for arbitrary invalid pointers.
