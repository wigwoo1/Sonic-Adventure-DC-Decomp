What changed
The sound graph now includes the original ring-buffer and finite-memory stream
joints, chunk splitter/wrapper, nested ADX critical sections, basic decoder,
streaming decoder, SPSD header helper and error reporter. These are genuine SDK
modules from pinned upstream 25a3d3154dbe657325e97dbe8c5291086f6af5c0.
The original SDK source stays an external dependency. Private generated sources
and combined SDK/game binaries are not selected for public releases.

Original ADXSJD_ExecServer now runs ADXB and ADXPD against actual stream-joint
function tables and buffers. This replaces no frontend with a fake success.
The same native G2 callback gate already used by sound SDK transport adapts the
original interrupt-mask calls. There is no second output client or duplicate
stream-buffer pool. These raw internal SDK APIs require a live creator-thread
audio owner and correctly sized caller-owned buffers. They are not public,
validated game-facing interfaces for arbitrary pointers or malformed media.

Native adaptations
- Keep all joint/chunk/vtable/callback pointers at 64 bits. Guest/native byte
  sizes: ring records48/72, memory records36/64, chunks8/16, SJD records144/200.
- Preserve the original SJD destructor's four-byte record-prefix clear. Using
  native sizeof(pointer) would instead clear eight bytes. The original stale
  fields remain stale after release; the actual used flag frees the slot.
- Register the SJD write callback after successful subordinate ADXB creation.
  The original registers through NULL on allocation failure. Native failure now
  returns NULL safely, releases the basic-decoder slot, and supports retry.
- Use unsigned halfword byte swaps. Select compiler-native variable arguments
  for the actual error reporter instead of SHC's four-byte stack walking.
- Select upstream GCC's initialized SPSD invalid-code locals. Invalid SPSD
  formats and WAV/SPSD playback are not qualified by the ADX tests below.

The original excessive-unlock behavior is observed, not silently repaired:
ADXCRS depth can reach -1 and stop masking until ADXCRS_Init. The eventual ADXT
owner must balance failure-path locks; original frontend double-unlock paths
cannot simply be exposed to game callers. No physical SH-4 interrupt timing
or new console hardware measurement is claimed by the host callback gate.

Remaining integration
The original game stream task still compiles but its deliberate, unexecuted
link audit requires12 real frontend services: ADXF_LoadPartition plus ADXT
Create/Destroy/EntryErrFunc/GetStat/GetTime/SetAutoRcvr/SetOutVol/SetSvrFreq/
StartAfs/StartFname/Stop. The thirteenth symbol, adxpd_internal_error, already
exists as actual local SDK state and needs colocation or correct data import.
This work recovers prerequisites below those APIs; it does not satisfy them.

Next adapt the actual ADXT/TLK task lifecycle, ADXSTM/ADXF/GDFS/AFS ownership
and original RNA output. sdk/sofdec/mw_sdcs.c provides mwSnd ports; it allocates
actual SDK PSTM banks and memory blocks. Its PCM producers must feed the same
existing AICA/output owner as effects. Preserve looping, time, volume, callbacks
and ordered shutdown. Replace the game's fixed0x0cca8000 work address with
owned music/voice buffers (184516/55428 bytes, with native alignment checked).
Do not open an independent unmixed WASAPI client as production music output.

How to check
Open analysis/jp_native_adx_stream_decoder_package.json and the source/proof
reports it names. The package binds each file by SHA256. Rebuild from the same
external upstream and prior ADX baseline using jp_port_tools/build_native_adx_
joints.py, then build_native_adx_stream_decoder.py. Each builder's --help lists
required local paths; use new output directories to preserve prior proofs.
Run verify_native_adx_joints.py and verify_native_adx_stream_decoder.py against
the resulting build and supplied Japanese 1ST_READ.BIN. Original retail inputs,
toolchain downloads and prior qualified dependencies must be provided locally.
