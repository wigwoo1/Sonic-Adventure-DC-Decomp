ARM sound-driver recovery checkpoint
===================================

The main game code runs on SH-4, while these separately loaded driver payloads
contain ARM code. Source recovery of the SH-4 upload wrappers does not recover
the driver payloads themselves. Both original disc images below are preserved
as separate analysis inputs; their candidate counts are not added to verified
routine counts or used as whole-game coverage percentages.

Input and upload spans
---------------------
The original SDRV header is 32 bytes. Recovered uploader 0x8c643ec6 reads the
length at header +8; 0x8c643ec8 advances the source by 32 bytes. The rounded
original disc read is retained when constructing these spans.

MANATEE.DRV: file 33,408 bytes; uploaded span 33,408 bytes starting at +32.
That span includes 32 actual zero padding bytes beyond the file's declared
size. SONICADV/MASARU.DRV: file 33,408 bytes; uploaded span 33,376 bytes at +32,
with no file padding included. The game loader's literal at 0x8c159d60 names
masaru.drv. Do not substitute MANATEE or assume identical upload lengths.

prepare_arm_sound_drivers.py checks original extraction hashes against the
actual disc sector reads and saves payload/header/vector hashes in
analysis/arm_sound_driver_payloads.json. Derived binary payloads are local
analysis inputs under work/sonic-adventure/arm-sound-drivers.

Analysis outputs and verification
---------------------------------
Ghidra 12.1.4_PUBLIC analyzes each upload span at base zero with ARM:LE:32:v4.
The eight original ARM branch vectors seed entry analysis: reset branches to
0x100, six exception vectors branch to 0x234, and the last vector branches to
0x248. Further calls, state/data accesses and indirect targets require review.

analysis/arm-sound-drivers/MANATEE.DRV.arm.bin:
  108 candidate functions, 108 draft C exports, 6,152 listed instructions.
  24,608 decoded instruction bytes; 8,800 bytes outside this instruction listing.
  53 draft warnings.
analysis/arm-sound-drivers/MASARU.DRV.arm.bin:
  108 candidate functions, 108 draft C exports, 6,154 listed instructions.
  24,616 decoded instruction bytes; 8,760 bytes outside this instruction listing.
  53 draft warnings.

Each directory contains function_index.tsv, initial_pseudocode.c,
instructions.tsv and program_metadata.tsv. Every listed instruction's full
four bytes and all sixteen vector branches were checked against the exact
upload images. Ghidra's loaded image hashes also match. Candidate addresses,
draft counts, source/tool/script hashes and outputs are pinned in
analysis/arm_sound_driver_inventory_verification.json.

These are machine-generated drafts, not buildable or behavior-verified source.
Code/data separation, indirect function discovery and real function boundaries
remain incomplete; vector thunks can produce duplicate-looking pseudocode.
Bytes outside the instruction listing include data and possibly undiscovered
code. None of these numbers measures whole-driver or whole-game completion.
ARM execution, sound-chip semantics and audible playback are not proven.

--------------------------------------------------
1. Run prepare_arm_sound_drivers.py with the project's Python interpreter.
2. Run ./ghidra/analyze_arm_sound_drivers.ps1 to import/analyze/export both
   payloads. Existing Ghidra/JDK installations under the project toolchain are
   required. -RefreshEvidenceOnly re-exports instructions/input metadata from
   existing projects; the image hashes prevent use with mismatched payloads.
3. Run verify_arm_sound_driver_inventory.py, then
   register_arm_sound_driver_inventory.py with the same Python interpreter.

The Ghidra Java scripts compiled/executed and the focused inventory validation
passed. No native ARM implementation was compiled and no ARM runtime tests
were performed for this inventory milestone. Overall project remains 10%.

Native bank/program selection and legacy alignment
-------------------------------------------------
source/sa_arm_sound_bank_select.c now executes the complete type-4 bank/program
selection path. Existing native dispatch/intake reaches it with no ARM service
callback. MANATEE and MASARU retain their actual different rejection behavior:
an out-of-range present-bank selection restores MANATEE's old bank pointer,
while MASARU writes its invalid selection marker and -1 bank pointer. Missing
MANATEE banks use the original embedded default header. Missing MASARU banks
retain the original -1 pointer and wrapped reads from low RAM; no invented
fallback/success validation replaces that behavior.

That MASARU path exposed a concrete instruction-reference gap: Unicorn 2.1.4's
default TI925T model joins adjacent bytes for the tested unaligned word reads.
ARM's pre-ARMv6 rule instead aligns the physical word access and rotates a
single-word load; word stores use the aligned physical address. The native
components now share source/arm_sound_memory.h for this rule. Byte transfers
remain byte-addressed. Existing recovered block transfers require an aligned
stack. Source: ARM Architecture Reference Manual, ARM DDI 0100I, section A2.8:
https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/1023/ARM-Architecture.pdf

arm_legacy_alignment_reference.py adapts only unaligned single-word accesses
in the reference run using that documented rule; aligned instructions still
execute in Unicorn. Correction counts and the adapter hash are recorded.
verify_arm_sound_alignment.py passes 32 word-load cases with two independent
hardcoded rotate tables, sixteen word-store cases and sixteen byte-store cases
across all four address offsets and both payloads. Adjacent bytes, complete
CPU/RAM and bus events are checked; the raw emulator mismatch is also checked.
This adapter is not an ARM7 timing or complete exception/hardware model.

verify_arm_sound_bank_select.py passes 1,152 direct command cases and 128 native
queued cases. Both drivers, two fills/flag states, high-bit command metadata,
three group/part pairs and bank indices, missing banks, zero/one/three-program
headers and indices 0/1/2/127 are covered. Exact active CPU/CPSR and all RAM
match original instructions with the explicit architectural adapter. Separate
checks validate selected bank/program/data pointers, rejection preservation,
saved old pointer and wrapped queue consumption. The missing MASARU cases

Existing helper/reset/main-loop/queue/pitch/error suites also passed after the
