Original behavior retained
The generic dispatcher sign-extends the low 16 bits of the event, shifts by
four, and selects the event-list head. Each callback receives its recorded
argument; the next link is loaded after the callback returns. Primary and
secondary dispatchers traverse their original heads with interrupt mask 6.
The ASIC body accepts event group 0x36, uses interrupt mask 4 and snapshots
masked normal status, shifted by 12. A nonzero normal snapshot has priority:
seven normal bits select events 0xa00 through 0xac0. Only when that complete
normal snapshot is zero does it inspect four error bits, selecting events
0xb00 through 0xb60. Ignored high normal bits still suppress the error path.
Original no-op event groups, signed lookup, callback order, stack/register
effects and reached pointer/privilege/missing-service errors remain intact.

Actual data-to-completion sequence verified
1. Original event registration installs the real transfer handler and argument,
   updates the channel mask and writes the ASIC entry into the vector table.
2. Original channel start configures and triggers the actual software register
   bank. The descriptor is active/incomplete; the SDK record is state 2/done 0.
3. Existing authored g2_transfer_host.c captures those register values and moves
   actual source bytes into mapped software Sound RAM. Its support code is not
   recovered game code and earns no recovery credit.
4. After successful movement, an explicit software pending-bit input is supplied.
   Original ASIC and generic dispatch select the registered transfer handler.
   That handler acknowledges the channel and invokes the original SDK callback,
   producing descriptor inactive/complete, record state 1/done 1 and no current
   record. No test supplies a completion flag or game-helper return value.

Evidence and scope
Each guest ABI call compares full CPU/FPU/RAM/VRAM/SoundRAM and ordered call
boundaries with an independent original-instruction interpreter. Masks,
register results and completed sound bytes are carried explicitly between
separate calls. This is not an uninterrupted earliest-startup comparison or a
resumed guest checkpoint. The software pending bit is an explicit platform
input after actual transfer success, not physical IRQ acceptance or timing.
Automatic runtime pumping and CPU exception entry/return remain unfinished.
Default REQUEST therefore still waits without explicit delivery.

Earlier full 2 MiB copies, full 8 MiB video clear and earliest-caller proofs
remain immutable historical evidence; they are not claimed rerun here. Prior
source/proof/build bytes, canonical registry fields and user requirements are
preserved except ten reviewed derived documentation/registry/audit paths.
