Original code and interpretation
The nine-instruction wrapper 8c10d914 calls the six-instruction leaf 8c10d926.
The leaf reads a signed 16-bit word at ff800030, zero-extends it, and masks 0300.
The wrapper shifts the result eight places and masks to values 0 through 3.
Original instruction order, delay slot, PR save/restore, registers and stack
effects are retained in source/sa_movie_status.c. The generator also retains
the destination register on a rejected signed read, before returning the host
failure status. This local fix does not modify earlier source or proof files.

KallistiOS identifies this port as PDTRA and uses these same bits for cable
status: 0 VGA, 1 nothing connected, 2 RGB, 3 composite. This supports the cable
status interpretation of the original routine; it does not prove all callers'
meaning or establish physical GPIO behavior. No KallistiOS code is copied.

Native platform interface
source/video_signal_bus.c/h adds an explicit caller-sampled 16-bit input at
ff800030 to the existing cache/register/peripheral chain. It accepts word reads
only, logs raw samples with event 21, rejects writes and other widths, and
delegates other accesses to the previous backend. Initial samples clamp to
16 bits. This is host policy, not a physical cable detector. PCTRA direction,
electrical inputs, Area-7 aliases, real exception vectors and output pixels
are not implemented. No game query or callback return is supplied as a fixture.

source/sa_movie_status_connected.c routes both original bodies in the existing
MOVIE startup chain. build_movie_status.ps1 builds 151 translation units with
strict warnings and the existing bounded-stall research policy. Previous APIs,
source, proofs and compiled artifacts retain their original bytes.
