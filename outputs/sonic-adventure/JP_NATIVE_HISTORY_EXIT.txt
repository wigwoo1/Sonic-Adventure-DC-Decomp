What changed

The same System instance can now start the actual native history provider and
attach its cleanup authority to the existing bootstrap registration. An explicit
guarded handoff also supports an independently initialized provider. Automatic
startup rejects an existing independent owner without altering it. Failed
constructors that retained real resources remain covered by System cleanup.
There is one actual UF record, flash manager/cache, history work allocation and
System registration. The old bootstrap callback body is unchanged.

Ordinary parent shutdown, early global exit and final delegated Exit all drain
the real card service first, then save/close history before sound, GDFS, RTC and
input are retired. Card completion may still record history while it drains.
Cleanup called from an active card or RTC callback is rejected before terminal
flags or cleanup counters change. The history provider queries the actual card
claim/activity; it does not create a substitute callback-activity counter.

JP_EXIT_HISTORY is a new explicit bit (4194304); older mask values are preserved.
Final binding requires this bit and transfers the existing history token only
after the other claims succeed. The tested late device-claim rejection retains
the earlier bootstrap registration and its history token. Successful ordinary
shutdown releases a finished nonterminal claim and can restart the complete
original parent in the same process. Terminal shutdown cannot restart/cancel.

The final history save accounts for elapsed play time even if an earlier
explicit save cleared its dirty flag. A real Windows sharing denial prevents
atomic profile replacement in the tests. The old complete profile remains
unchanged; native UF work, profile ownership, token and needed RTC/audio/GDFS
services remain alive for recovery and retry. Successful retry releases them.
VMU media and LCD remain caller-owned. No user profile is imported or reformatted.
