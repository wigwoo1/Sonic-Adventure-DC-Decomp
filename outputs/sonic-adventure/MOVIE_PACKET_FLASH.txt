The authored flash_storage service owns no default identity or settings. Its
caller supplies mutable bytes, up to five disjoint partition extents and a
write-enable policy. It exposes info/read/program/erase operations at actual
firmware-call boundaries. Tests compare whole RAM, flash bytes, metadata,
counters and guest/host error results. Only one-to-zero programming is accepted;
an incompatible write fails atomically before changing bytes. Erase changes
only the declared partition. This is untimed host policy, not recovered BIOS,
physical protection, partial hardware programming or persistent file saving.
