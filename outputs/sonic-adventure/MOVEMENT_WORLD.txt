Recovered behavior
0522c0 takes XYZ through FR4/FR5/FR6 and query radius through FR7. It clears and
produces the 16-bit nearby count at 8c754ef0 and 12-byte entries at 8c754ef4.
It scans static object entries in reverse order. The 10000000 flag selects the
actual identity/rotation/point-transform callees. Other objects use their model
centre directly. Distance is compared with the squared sum of query radius,
model radius and the original 30-unit margin. Optional dynamic records use the
original enable/presence/count gates and sphere test. Both paths stop at 1,024
selected objects. Actual matrix push/pop and other callees run in these tests.

63a8e0 loads the original identity table at 8c67c640. With R4 zero and ordinary
PR0/SZ0 mode it loads the inactive matrix-register bank. With an explicit R4
output it copies through active FP scratch registers to RAM. The raw transfer
order matters when input/output overlap. Paired-transfer modes retain their
original, different memory effects; they are not claimed to be an ordinary
identity-copy API. Null R4 with PR1 stops at the existing FSCHG numeric guard.

028bfe takes the query through R4. It clears its polygon counter, calls the
actual vector-length helper and 0522c0, then matches world nodes by object
POINTER against produced nearby entries. It walks both polygon-list directions,
filters bounds/distances, writes the global candidate array and each node's
selection pointer/count, and stops at 96 candidates. Enabled diagnostic text
uses the actual recovered text caller. This description does not qualify every
path of the owner or establish natural scene initialization.

Remaining owner evidence
At 028ca6, the taken outcome is impossible under original normal entry and
stable mapped RAM: an earlier comparison requires lower-bound > key, then the
later branch requires that same key > lower-bound. Reloaded operands, address
bases and numerical controls are unchanged. NaNs cannot make the first ordered
comparison true. The byte-backed proof also checks graph predecessors and the
pinned software-comparison helper. No original instruction is removed.

028cba -> 028cbc and 028e0c -> 028e0e remain OPEN, together with instructions
028cbc/028cbe. These paths need null-pointer states after earlier null+10 reads.
The present mapped-RAM/bus interface stops at those reads. That does not prove
physical Dreamcast unreachability: low addresses can involve boot ROM, which
is not qualified here. Do not supply guessed BIOS bytes or assume that authored
sentinels establish real game invariants. Trace actual list construction or
recover verified low-address read behavior before crediting this owner.

Scope and preservation
Successful geometric owner paths are qualified in PR0/SZ0 software profiles.
Raw identity transfers have broader mode comparisons. Physical FPU behavior,
exception delivery, MMU/boot-ROM reads, GPU output, natural world construction,
complete 0730d8 movement, frame timing and full gameplay remain unqualified.
The existing 029b00 outcome 02a48c -> 02a4a8 remains open as before.

The new bridge is exactly the old 251-source bridge plus three entry routes,
13 actual return sites and 13 continuation exports. CPU/reference interpreter,
guards, production observer, comparison logic, raw session and ABI are retained.
There are no new source wait bounds. Of 471 explicit continuation exports,
71 nonlocal routes are qualified and 400 remain unqualified. The 13 new exports
do not independently qualify nonlocal resumes. The old source/proof/build bytes
remain available; the new DLL and import library are additional artifacts.
