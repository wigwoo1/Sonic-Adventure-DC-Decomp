Native Windows evidence

The unchanged upstream src/system/task.c and our authored heap bridge compile
to Windows x64 objects, both with empty diagnostics. The initial attempt caught
the SDK's 32-bit size_t conflict with the native compiler. jp_host_types.h uses
the native type through the SDK's SIZE_T_DEFINED guard without editing upstream
code or widening Uint32. The second attempt reaches the linker, which names
eleven unresolved whole-translation-unit imports. The attempts stop there.
There is no linked DLL and no heap/task behavior test. Private object files are
excluded from public artifacts. See jp_native_heap_build_v2_verification.json
and jp_native_link_dependency_inventory.json under analysis/.

The dependencies identify a concrete first integration group: task, collision
and event lifecycles plus real Ninja matrix/vector providers and their state.
Some .c providers contain SH-4 assembly guarded out under Clang, so compiling
declarations alone does not implement them. The next native step must implement
or adapt the actual providers with explicit host/data layouts and behavior tests.

English-localization evidence

The supplied discs contain 2,106 JP files and 2,832 USA files, with 1,748 common
paths. Directory-name candidates are research leads, not equivalent resources.
The USA disc includes a separate SONICADV/EVENT_ADX_US.AFS English voice archive.

Private AFS indexing verifies 2,088 JP Japanese clips, 2,044 USA Japanese clips
and 2,044 USA English clips, with bounds and payload hashes. VOICE_FILES=2148 in
the JP source is a load capacity; the observed JP archive fits it. Two-sided
unique Japanese payload identities provide 1,664 cross-version pairs. Each pair
was independently byte-compared. Of these, 1,539 change index and 125 keep it;
424 JP entries lack a unique identity anchor. Five adversarial matcher checks
cover moved IDs, duplicate ambiguity, unmatched payloads and empty entries.

The resulting English indices are candidates only. English bank binding, event
cue IDs, text/voice timing and playback remain unverified; no English audio or
text has been activated. See jp_english_localization_inventory.json,
jp_english_voice_archive_inventory.json and jp_english_voice_candidates.json in
analysis/. Original stage text/timing is imported through generated disc-data
includes, so localization requires explicit table/font/UI conversion too.

Reproduction and next milestone

jp_port_tools/ holds the authored worktree builder, qualifier and inventory tools.
Run the Linux tools in the named WSL distribution with explicit --workspace,
--source/--destination or --checkout arguments, matching local disc inputs and a
fresh destination. Run the Windows native probe with --upstream pointing to the
pinned external source and --compiler to Clang. Existing reports/output names
are write-once; use a fresh workspace for a full replay. These are research
workflows, not a portable game installer.

For a beginner, start with the passing GCC report and integration plan. The
native link failure and candidate voice mappings are explicit limits, not a
failed GCC build or completed localization. Keep Sol High for the native ABI
and real SDK dependency work; Luna Low suits routine reviewed publication.
PC gameplay, 60/120/240 FPS/8K/settings, SUPIR textures, Android, stereoscopic
3DS and N64/PlayStation work remain required. Texture Off must sample no textures
and use vertex/material colours. Retail assets, RAM, toolchains and credentials
remain private; historical Windows research DLLs are incomplete and non-playable.
