What changed
The actual sound_system_init closure now runs under a compiled native owner.
It executes ten original game functions: sound_system_init, sound_init_driver,
midi_open_ports, sound_set_space, sound_reset, sound_set_fx_01, sound_set_fx_23,
qsound_reset, midi_reset_all and midi_reset. Their single real global state is
compiled beside the previously qualified real SDK, not copied into separate
per-function test states. The full sound.c remains the intended implementation;
this linked closure does not replace its unavailable gameplay/stream providers.

The owner borrows the real initialized System/GDFS/wait services. It creates
the actual AICA/output owner and G2 transport, then executes the game's original
driver path and MIDI initialization. MASARU.DRV is opened and read through actual
GDFS. Its 33,408 bytes occupy 34,816 bytes of sector-rounded, page-aligned native
staging with no-access guard reservations. The original fixed WORK_AREA address
is never dereferenced. Header type, version and payload bounds/alignment are
validated before the SDK can read the ARM program. Staging stays live through
transport/SDK retirement because released original descriptors retain pointers.

The successful original order is preserved: SDK init, DMA mode, outer descriptor,
first actual driver boot, descriptor release, second actual driver boot using
the original released-slot alias, then the real frame/vsync callback. The actual
ARM driver runs 88,200 boot frames; eight real MIDI ports open, the native copied
stereo/mono mode is read, effects/QSound/slots reset, and 32 MIDI controller-reset
commands are produced. All 39 actual queued commands are independently checked
including every parameter/padding byte and the pending marker. The FX levels
follow the actual driver's debug56 fine-level behavior, giving80 for outputs0/1.

The native syCfg session owns copied settings and borrows the original work
buffer until exit. It validates a real session header/generation, supports an
unaligned char buffer, returns the configured mode and applies explicit mode
changes to its session. It never touches console flash/low RAM. This is not a
persistent settings-file implementation; that integration remains required.
Native synchronous config retries are bounded and actual failures propagate.

Void original startup helpers now stop on real dependency/SDK errors rather
than proceeding with invalid handles or reporting a ready owner. Failure tracks
its original cause separately from any failed cleanup. Shutdown first unbinds
the actual frame callback, drains real G2 completions, closes G2, retires SDK
state, joins/closes actual AICA/output and finally releases staging. A failed
step retains unfinished resources for a same-thread retry. Cleanup never takes
over a pre-existing core or callback binding. Reentry and foreign-thread calls
cannot replace/retire a live owner or alter query output buffers.

The frame dispatcher binds a uniquely named bridge to the actual source-local
SDK server. It does not call the presenter's identically named forwarding thunk
recursively. The full original sound_send_queue is still unavailable and no
dummy queue is bound; real frame calls report that limitation explicitly.
