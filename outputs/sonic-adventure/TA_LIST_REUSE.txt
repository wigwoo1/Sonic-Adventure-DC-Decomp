Guest TA list-init and reusable command collection

Status: VERIFIED within the explicit untimed host profile. Approximately 10%
weighted whole-project milestones, not measured code coverage. Not a playable port.

The original frame code submits rendering, pulses TA reset, selects alternating
parameter/object-buffer bases, then writes bit31 to TA_LIST_INIT. The old research
collector retained all accepted packets cumulatively and would exhaust its fixed
64 entries. The new standalone ta_list_lifecycle.dll retires current collection
only after a successful original TA_LIST_INIT strobe. No harness queue reset or
capacity increase is used. Existing game/support C, binaries and proofs remain.

At this guest write, native code preserves a copy of the retired context, clears
current/partial command storage, resets list-decoder/current-collector cursors and
rebases the pixel capture cursor. The already submitted immutable job survives;
its words, descriptor, completion ownership and pending interrupt events are not
discarded. Pending list events remain until original ASIC acknowledgement. The
next context can be collected while the prior job is still owned by the backend.
TA reset requests are observed separately; TA_LIST_CONT is forwarded and does not
discard complete collected packets. This does not qualify full multipass/partial
continuation or every soft-reset behaviour, or physical TA parameter-RAM encoding.
