source/native_disc_sector_reader.c starts the native port's replacement data
path. It is newly written platform code and earns no game-routine credit.
It reads 2048-byte data sectors from a configured cooked-2048 or raw-2352
MODE1 track using a host read-at callback. The caller supplies the track's
base LBA, sector count, file offset and layout. The track reader does not
parse a GDI or translate firmware FAD requests; those belong to later layers.

progress from a host error. Earlier sectors remain delivered after an I/O
failure; the callback may have touched the failing sector's bytes. There is
no global state. The host callback must fill every requested byte or return
an error. Concurrent file access requires a suitable read-at implementation.

Native request ownership and queue
----------------------------------
source/native_disc_queue.c and source/native_disc_queue.h add an eight-slot
host request queue over the sector reader. This is new platform code with its
own explicit API, not a claim of firmware ABI or timing equivalence.
Submit takes an LBA/count and borrowed output buffer. Status returns queued,
complete, cancelled or failed, completed-sector count and any host I/O error.
Each step services at most one sector, round-robin across requests. Cancellation
keeps already delivered sectors. Terminal slots remain owned until release;
handles are never reused during a session and exhaustion is rejected.
Zero-length requests complete without I/O. Transport errors belong to the
request, so processing other requests can continue. Each queue owns its state.
Step/cancel/release/submit reject mutation during a read callback.

Initialize each queue before use. Reinitialization starts a new session and
invalidates old handles; do not reinitialize while requests or callbacks use it.
The API is single-threaded. Callers retain valid output buffers until release;
they must serialize access and ensure separate requests do not overlap buffers.

Nine verified scenario groups cover round-robin progress/partial cancellation,
slot capacity/release, stale handles, zero-length reads, invalid inputs,
separate queues, transport failure, callback reentry and original-disc reads.
Four simultaneous requests reproduce original-disc file hashes, including the
entire 1ST_READ.BIN, through 3304 native queue steps.
Evidence: analysis/native_disc_queue_verification.json with source/header/DLL/
verifier/inventory hashes. build_and_verify.ps1 includes the focused workflow.

Runtime-service subset
-----------------------
sa_disc_service in source/native_disc_read_command.c now adapts operations
0 (submit commands 16/17), 1 (status), 2 (one queue step), 3 (host startup
validation) and 8 (cancel).
It writes the four-word status detail block: error 1, error 2, transferred byte
count and ATA status. Invalid guest status spans fail before any mutation.
Unsupported operations return a host error, not fabricated successful output.

Documented platform status values are -1 failure, 0 not found, 1 processing,
2 completed, 3 streaming and 4 busy. This reader implements no streaming.
Reference: KallistiOS dc/syscalls.h, cd_cmd_chk and cd_cmd_chk_status:
https://kos-docs.dreamcast.wiki/syscalls_8h_source.html

Host policy choices, not proven original firmware behavior: one sector per
process call; cancellation reports failure with error 1 = 0; I/O failure reports
generic error 1 = 8 and the host error as detail; a terminal status consumes its
handle and releases its slot. Later polling reports not found. This prevents
slot leaks in callers that never invoke the new host API's explicit release.
Transferred bytes remain available in the first terminal response.
Operation 3 validates the already configured host queue is idle with no owned
slots. It does not discard pending or terminal requests or reset handle identity.
Four tests cover empty success, queued rejection without mutation, unreleased
terminal rejection, and success after terminal status releases ownership.

21 real-disc scenarios run native submit/process/cancel/status through the
original device-status formatter and lower tail. Pending, partial, complete,
cancel-before-progress, partial-cancel, transport-error and missing-request cases
cover three RAM aliases. Full RAM/GPR/SR/PR/FPU match retail formatter execution
