What changed

The original loader's complete five-function queue runs against the actual
native GDFS and local Japanese v1.007 disc data. It retains the original fixed
16 slots, one selected read/file handle, lowest-waiting-slot scheduling and
original add/initialize/selected-slot bodies. There is one actual queue and one
actual GDFS handle pool. Three original function bodies are unchanged; serve
and cancel are explicitly adapted for native failure and ownership rules.

Native enqueue requires each destination's real capacity. It checks a bounded
filename, 32-byte alignment, sector-rounded capacity, address overflow and
overlap with other live destinations. A read's actual size and frame address
are checked again when it starts, so a changed directory entry cannot silently
redirect the queued work. Diagnostic snapshots cannot overwrite a live buffer.
The caller keeps a destination alive until its slot is FREE or cancel succeeds.
Names must identify files in the current GDFS directory, with no path separators.

The original serve algorithm defers while another GDFS client has work. All
pending read/seek/busy states retain the selected slot. Completed byte counts
must match the actual sector-rounded file size before its handle/slot retire.
An actual open, metadata, request or media error is reported instead of causing
the original unbounded reopen loop. The failed slot and any real open handle
remain live until checked cancellation succeeds. Cancellation closes/drains the
actual read before marking slots FREE; a rejected close cannot release buffers.
Even the short-lived metadata-probe handle remains owned if its close fails.

The same GDFS owner has a nonterminal client lease and stamps only queue-owned
opens in its existing handle records. Other sound/file clients remain usable.
Independent mutation, close and callback replacement of a stamped handle are
rejected. Authority is suspended inside real GDFS callbacks. GDFS cannot shut
down, reinitialize or commit terminal finish while the queue lease remains;
rejected terminal finish can still cancel its uncommitted claim. Queue shutdown
first cancels its own work, then releases this lease. It does not own System,
RTC, frame service or any caller destination, and installs no user callback.

Limits and next milestone

The caller currently closes the queue before System/global Exit. GDFS rejects
early independent destruction while the queue lives, but System/Exit does not
yet own the queue's terminal lifecycle. Add that to the existing registration
before integrating the complete original game_init. Preserve one queue and
actual GDFS lease; drain its work before closing GDFS, RTC and caller buffers.

An actual OS cancellation timeout was not forced by these tests. The source
audit checks retention order, and real callback/thread rejection and pending
cancellation are exercised; these do not prove that timeout branch. Raw legacy
read_queue_add has no capacity argument and is not exported. Future original
callers need a checked native buffer contract; silently trusting that raw entry
point would reintroduce the original overflow risk. The typed API runs the
original add algorithm after validating the native contract.
