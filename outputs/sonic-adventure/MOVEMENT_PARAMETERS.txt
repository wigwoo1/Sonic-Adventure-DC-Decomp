Recovered behavior
R4 supplies an object whose unsigned byte at +9 selects a character table row.
R5 receives an output scalar at +3c. R6 supplies the state record; R7 is a flag
mask, not a pointer. There is no fifth stack argument. The Ghidra C draft's
parameter names/types are not authoritative; the original instructions are.

The routine first ORs R7 into state +5c. It then reads state mode +1e4 and the
original table at 8c1bdfe4, using stride 84 and fields +78, +58 and +3c. It writes
state fields +114, +f4 and +d8 respectively. Mode bit 2 takes priority over bit
400000. These modes apply original binary32 scaling constants, including the
special half scale for selector 5. Otherwise it copies the table words.

Scalar priority uses R7 bits 8, 4, 10 and 80, producing the original approximate
0.15, approximate 0.10, 0.5 and 1.5 constants respectively; default is 1.0.
Memory offsets, addresses and bit masks in this guide use hexadecimal.
The selector is reread after each field store. Table data is also read in order;
copying all inputs first would change behavior when pointers overlap.

Remaining branch proof
To reach the repeated bit-2 test at 07532a, the earlier test at 075234 must find
that bit clear. The only intervening admitted path makes no RAM stores or calls
and rereads the same state word at R6+1e4. The repeated test therefore also finds
the bit clear, so BF 07532c cannot take 075382 under normal entry, fixed original
code and stable mapped RAM. The proof checks original bytes and predecessors.
It does not assume separate input/output/table buffers. Asynchronous physical
memory changes, arbitrary mid-function entry and self-modifying code are outside
this proof's scope. The branch remains present in the recovered code.
