Qualified native vertex initialization and startup integration
Whole-project estimate: about 10%; goal active. No playable PC port yet.

The adapted njInitVertexBuffer now completes the real Ninja blank wait,
configures the actual native vertex queues, commits SDK scalar/list/config
state and refreshes the original shared texture maximum through njCalcTexture.
The texture owner exposes a cache operation, avoiding Windows DLL variable
declaration conflicts and retaining exactly one shared SDK cache variable.
The higher lifecycle module imports frame/presentation; lower modules do not
import it. Failed waits and allocations clean up only the armed Ninja handler.
Recycled unrelated callback slots survive cancellation.

Native adaptations and remaining scope
Console P1/P2 aliases, TA bypass pointers and contiguous/banked command heaps are
replaced by separately owned growable native queues. Native texture free/maximum
block queries mean remaining host budget, not console fragmentation or an OS
allocation guarantee. SDK pVertexBuffer is NULL for these noncontiguous queues;
the original logical word count and share fields are retained. Existing native
renderer/presenter already own framebuffer allocation. The generic hardware
kmSetSystemConfiguration lifecycle and caller-supplied console command-buffer
branch are not implemented/qualified here. Main/movie use no supplied buffer.
Full system_boot_init, audio/card/VMU/text-style/cable startup services, gameplay,
English and later platforms remain unfinished. No full game EXE is published.
The matching Japanese baseline/GCC baseline and historical USA research remain
separate, preserved evidence; they do not demonstrate native gameplay.

Public artifacts and reproduction
Four new support libraries contain one exact authored object each for their
separate frame/presentation/higher-lifecycle roles. They are not a combined game
or standalone executable. Original SDK/game objects, diagnostic DLLs, retail
inputs/fonts/textures and screenshots remain private. Pinned upstream sources
remain an external dependency with original notices and unresolved redistribution.
All historical archive payloads remain byte-identical.
