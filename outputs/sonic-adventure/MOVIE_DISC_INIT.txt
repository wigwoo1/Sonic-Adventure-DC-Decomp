Warm and cold controls
The retained common RAM seed has a prepared filesystem at 8cc80000. The warm
earlier-caller profile retains it, reads no media and returns guest -8. It is not
evidence of fresh filesystem creation. The new cold-filesystem control clears the
filesystem and interface roots explicitly to their original zero values, then
executes original producers and the existing supplied software hardware profile.
It creates root 8c6946e0, reads real image sectors and returns zero with flag one.
This is staged initialization in declared RAM/peripheral conditions; it is not
proof of complete retail reset ordering, physical hardware timing or gameplay.

Small direct contexts with four-entry directory capacity legitimately return
guest -12 after two reads. Misaligned contexts return -14, transport-failure
profiles return -4, and an already-initialized context returns zero. These error
paths execute original code; no return is supplied to make the caller advance.
Null/owned temporary descriptors return -13 before queuing media I/O. The separate
free-descriptor profile retains the existing bounded read-wait stop. Original
signed byte-copy, record/parser, signature, endian and lookup fields are checked
independently, including overlap, guards, empty/missing records and memory faults.

Version-model correction
The unchanged native platform copies exactly sixteen bytes of its identity string,
SA-NATIVE v 1.00. This identifies the host backend; it is not copied Dreamcast
firmware. The old Python test model appended NUL and assigned seventeen bytes to
a sixteen-byte slice, growing simulated RAM and shifting subsequent data, including
saved return addresses. That previously unexercised path is corrected in the new
disc_init_platform_reference.py. boot_disc_reference.py and older proof/source/build
bytes are intentionally preserved. Use the new model for this integration.

The correction passes explicit C/model comparisons at all three address aliases,
with unchanged buffer guards, fixed RAM length, matching queue/status state and
no transport call for the identity response. A retained regression witness
demonstrates the old model's extra byte. No native backend code or identity bytes
were changed. The auxiliary py-spy profiler is a toolchain diagnostic, excluded
from published game/source-matched build archives:
https://github.com/benfred/py-spy

Control flow and remaining work
The original thunk 8c600032 jumps to 8c601618. That wrapper installs the original
interface table 8c66c4b4 and calls its 8c600038 method. The adjacent original body
is therefore reached through the interface, rather than directly by the thunk.
The system interface returned by 8c645328 is also original data. Native disc queue
policies, finite raw clocks, revision profile and all prior research wait limits
remain unchanged; no new firmware, IRQ, DMA or timing model is introduced.
