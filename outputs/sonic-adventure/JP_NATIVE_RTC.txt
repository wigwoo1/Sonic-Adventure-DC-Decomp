What changed
The native RTC service now uses Windows local civil time, expressed in the
original unsigned 32-bit seconds since 1950. It is independent of the paused
game timer and logical frame rate. The actual original vblank chain calls a
correctly typed native thunk at original priority 92. Original calendar/date
ordering, weekday/moon calculations, cached/direct/full-read selection and
two-reading filtering are compiled unchanged from pinned sg_syrtc.c. Ten
original function bodies are reused. The unchanged original card_get_time
caller, compiled with original SDK declarations, consumes this actual service.

The console's force-read loop could hang forever after the count changed past
its initial reading. The native boundary instead requires four equal successful
readings, adopting a fresh baseline after changes, within sixteen total attempts.
Persistent failure or an unstable provider returns an explicit error and keeps
the prior cached count/output. Transient failure can recover after four reliable
readings. There are no AICA/G2 register reads or successful register-write stubs.

syRtcSetDate applies a real session-local offset to the clock seen by the game.
The offset continues to advance with host time; the OS clock is never changed.
The offset currently resets on shutdown. Persistent user clock preferences,
timezone selection and any offline Chao behavior require separate integration;
they are not implied by this service. Original 32-bit range ends during 2086;
dates outside it, invalid calendar fields, NULL and overlapping conversion
outputs reject without wrapping or corrupting caller data. The original SDK's
calendar/moon semantics are preserved inside this supported count range.
Console-address logging mode is explicitly unsupported, rather than accepting
a truncated 32-bit address on a 64-bit host. DIRECT=1 and FULL_READ=2 work.

Lifecycle and exit
The real clock/wait owner is initialized first. RTC initialization must then
succeed before callers use timestamps. No callback capacity, missing timing
owner and provider failure cannot masquerade as successful initialization.
Source callers that ignore an RTC error are not proof of safe full startup;
the remaining native parent coordinator must propagate service failures.
One game thread owns lifecycle and reads. Recursive provider mutation and
foreign-thread calls reject. The chain record's original 0x80000000 active bit
is retained; priority comparisons mask that bit. Callback identity is checked
before deletion so a recycled handle cannot delete somebody else's callback.

The general native exit service now selects RTC=65536, delegating final-close
authority with a creator-thread 64-bit token. It removes RTC before device
quiescence or a separately owned wait service closes the callback pool. Tokens
cannot be stolen by truncated/wrong values or reused after cancellation.
Ordinary close/init/configure reject after delegation. Cancellation is allowed
until first final-close attempt. Committed retries use the same token; an
unexpectedly removed callback fails and preserves later owners for recovery.
Failed later RTC/device claims cancel earlier uncommitted heap/RTC claims.
Unexpected cancellation failure retains real cleanup authority in exit state.
Existing masks ALL=16383, WITH_DEVICE=18422 and WITH_DEVICE_SDK_HEAP=51190 retain
their meanings. New WITH_DEVICE_SDK_HEAP_RTC=116726 adds RTC. Classic native
ownership tests still execute unchanged. No same-process game restart is claimed.
