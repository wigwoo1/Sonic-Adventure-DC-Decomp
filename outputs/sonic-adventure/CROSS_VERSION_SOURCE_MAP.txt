Verification and preservation

Eight adversarial matcher checks pass: changed tail constants and addresses,
duplicate spans, alignment changes, short returns, truncated ambiguity and
invalid instruction boundaries. The independent checker re-reads original
inputs and all reported spans, checks source/table hashes, and reclassifies
the data. These tests check the research tool, not game behavior. The prior
310-C-source native DLL, normal checkpoint, historical source/proofs and all
2,887 Windows research builds are preserved. No native C was changed or
rebuilt for this analysis-only update. Earlier runtime proofs retain their
original scope; they are not counted as new tests here.

Research files are under analysis/cross-version-source-map/. The Japanese
matching report, raw build/check/test logs, source inventory, candidate map,
Ghidra observations and independent verification report are provided as hashes
and metadata. Retail images, original/rebuilt game binaries, textures, RAM
captures, private diagnostic images and toolchain bundles are excluded.

Reproduction and source access

cross_version_tools/ contains our exact workflow sources. It imports the pinned
upstream MIT build/parser tools rather than copying upstream game C. The two
shell sources keep their exact bytes under .sh.txt names for compatibility with
the historical publisher's text allowlist; restore their .sh names to execute.
The recorded workflow uses the separate WSL distribution sa-dc-source-review,
Ubuntu 24.04.5, and /root/sa-source-review. It expects matching private retail
inputs and historical workspace paths. To replay in a different workspace,
adapt paths in copies and use fresh output names: proofs are write-once. A
checkout alone does not include the required disc, toolchain or native-state
producer chain. The reports describe the actual runs, not a portable installer.

Upstream's README licenses its build tools and tests under MIT but gives the
remaining game source no license. This update imports no upstream game C and
assigns it no license. Public game-source reuse permission remains unresolved.
The upstream GCC build targets little-endian SH-4 and adds documented 60 FPS
and 16:9 modes; it is not an x86/ARM port or a generalized 120/240 FPS solution.
