Qualified body

Verification

-Werror without the C runtime. All 19 full-state comparisons pass: ten normal
complete direct-clear profiles, four injected write failures, three original
hardware-failure loop profiles, a returning mode-selector profile and an earlier
startup caller that completes its clear before its actual unresolved callback.
Six calibration profiles independently match the compiled decoder against the
existing Python instruction executor for 1, 2, 3, 17, 257 and 4096 iterations.

Every original native loop/helper call runs. A separate verification-only C
instruction decoder also executes every original loop/helper instruction:
33,554,432 instructions per complete clear, including delay slots. It does not
replace the loop with memset, a bulk fill, a guessed return or a skipped callee.
Its 16 code rows and three setup literal words are checked against the retail
instruction evidence. The port itself still uses statically translated C.

At every native helper boundary, exact register-sequence and FPU/FPUL invariants
are checked; every successful write checks address, zero value and four-byte
width. Counts, first/last states and ordered streaming fingerprints additionally
match independently decoded execution. Fingerprints are not treated as
collision-free proofs. The clear's logical reference event span is compressed
in memory; all native writes/reference instructions still execute. Reports label
sampled VRAM write lists as truncated and retain exact full-stream counts.

Final comparisons retain full 16-MiB RAM, eight-MiB VRAM, all CPU registers,
FPU banks, FPSCR/FPUL, special and banked state, software device state, finite

The first and last words and complete byte image are covered by the full compare.
