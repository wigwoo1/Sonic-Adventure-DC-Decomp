Sonic Adventure Dreamcast Rev A: buffer upload and transfer interrupt path

Overall completion remains approximately 10% by weighted milestones, not measured
code coverage. The goal remains active. This is an incomplete Windows research
library, not a playable PC port. All requested ports, frame rates, 8K output,
SUPIR textures and settings remain unfinished. Texture Off must disable sampling
and use vertex colors.

What the transfer test actually does

Original 645de0 initializes the exception vector and original 651520/653640
installs the graphics callback at VBR+224. Original submission code programs the
real channel-2 DMA registers. An authored, untimed platform service copies the
actual source bytes to video memory before recording hardware completion.
At the original SDK polling return, the platform accepts IRL9, event320,
priority6, when the actual graphics mask permits it. The original vector/context
code calls 652210, which acknowledges status bit19 and calls original 650e40.
That game code retires the active queue record. Original exception restoration
and RTE return to 65100a; original 651000 observes completion and returns.
No host code changes game queue completion flags or supplies helper results.

Three authored platform additions receive zero original-code recovery credit:
  A400 64-bit VRAM aperture, mapped to the existing bank-linear A500 storage;
  channel-2 texture DMA for ports11/13 and linear modes0/1;
  ISTERR write-one-to-clear status, with its raw accesses separately traced.
The existing G2 scheduler, old source/proof files and compiled artifacts are
preserved. The error status was previously generic storage: storing all ones
there falsely created errors. The new policy acknowledges bits instead. New
comparisons use this explicit correction; old evidence is not rewritten.

Verification

78 upload/initialization cases pass 1,793 independent checks. They exercise
ordinary, mip and VQ formats; original size tables; options rejecting a request;
aligned DMA and CPU fallbacks; tails, masks, queues, cache writebacks and waits.
Independent expectations check the complete 8 MiB video memory image, original
source and descriptor preservation, all queue records and hardware counts.

23 interrupt/queue cases pass 334 checks. They cover both queues, wrapped slots,
all relevant queue control bits, empty queues, 32/64/68-byte synchronous uploads,
two-part synchronous VQ uploads, and disabled-mask/runtime controls. Those last
controls genuinely remain waiting with status-4; completion is never invented.
Every comparison also checks complete CPU/FPU/RAM/VRAM/Sound, peripheral, banked,
exception and runtime state, with ordered call boundaries against original
instruction execution.

229 fresh regression comparisons pass 4,077 checks: 66 root, 28 constructor and
135 accounting cases. Two historical negative cases described A400 output as
physically invalid. The new platform supports that aperture, but the preserved
old accounting adapters still reject it. Those two cases are explicitly excluded
from the new regression count; A400 output from those particular old adapters
remains unsupported. Their old implementation, bounds and proof bytes are kept.
Other earlier comparisons remain retained evidence and were not all rerun.

Platform-only tests check a bijection of all 2,097,152 aligned aperture words,
1,612 native aperture calls, 41 DMA cases and three error-status alias cases with
4,884 independent checks. Width/alignment/range rejection, partial device failure,
unchanged source RAM, complete data/register ordering, IRQ acknowledgement,
retained traces and overflow counters are covered. These are not game routines.

Two fresh uninterrupted startup profiles execute from declared original entry
0546c0: warm4,373 / cold585,671 boundaries. The exact published203-source boundary
prefix matches through 65393a. The real32768-byte upload now completes through
the A400 aperture; original startup continues to unsupported routine60edb0.
The full 8 MiB clear, both 2 MiB Sound fills, both33376-byte sound transfers,
original G2 interrupt/RTE/REQUEST returns, all1,065,282 Sound events with no drops,
all39 pending SDK records and all32 MIDI sends remain checked. Startup uses
explicit platform/flash inputs; no checkpoint, priming, shortened copy/clear or
older cold capture replaces actual execution.

Limits and reproduction

DMA is untimed and limited to the declared texture protocol and first8MiB VRAM
range. Polygon/YUV DMA, wrapping outside the declared range, physical interrupt
timing and concurrent mutation are unfinished. Immediate completions may
coalesce while another job is backlogged; the tests claim the declared one-job
and separately submitted synchronous two-job lifecycle only. Direct fixtures
have coherent mapped/aligned queues and a disjoint private guest stack. Arbitrary
corrupt cycles, destructive aliases and invalid zero-length CPU copy behavior
are not qualified. Busy-wait research guards stop without faking completion;
strict unbounded sources are compiled separately. No reset boot, visible pixels,
audible output, gameplay or playable executable is established.
