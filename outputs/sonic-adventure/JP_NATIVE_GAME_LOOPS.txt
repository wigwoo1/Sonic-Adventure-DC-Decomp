Actual loop playback
The original game music task requests unmodified Japanese JINGLE_5.ADX. Its
header declares1194791 samples/channel at44100Hz. The loop runs from sample
136352 to1194788, with byte offsets153600 and1344372. Audio begins at byte204.
The first natural loop is about27.1 seconds into the source; its repeating span
is about24.0 seconds. These positions/header bytes are never rewritten.

Four fresh-process runtime cases pass323,947 checks:
- CPU and DMA paths each traverse two complete original decoder loops and then
  continue decoding. Every reported output sample matches the independent
  step-aware binary32 recurrence, including predictor history across loops.
- The real file EOS callback seeks to sector75 before the decoder trap reaches
  the loop end. The original callback addresses and full-width player contexts
  remain installed. Offline snapshots check exact trap resets of source sample,
  trap count and compressed offset; there are no substituted callbacks.
- Actual output free capacity limits the original producer. The test observes
  shortened/blocked producer steps with sufficient compressed input and checks
  that output never exceeds the real available capacity. No producer chunks are
  borrowed out of order, and no artificial queue or completion is used.
- All captured mixed ARM-firmware PCM bytes and full2MiB sound RAM agree between
  separate CPU and DMA runs. CPU starts no DMA; DMA retains real transfers across
  loop boundaries. A bounded private WAV spans the actual first loop boundary.
- A new request at the first natural boundary executes the real stop/start
  path, resets the original loop/decoder counters, keeps the same actual task,
  players and native work, and decodes a fresh independently verified prefix.
- Automatic elapsed-time playback reaches a real loop using the existing native
  wait, sound clock and single muted output worker. A wait may deliver several
  audio steps, so timed snapshots validate consistent post-loop continuation;
  exact callback-entry resets and every sample are covered offline. Independent
  compressed-source cursors/sample modeling apply to the offline cases only.

The original ADXB stereo pad-accounting quirk is retained and modeled explicitly.
Its block counter counts both channels when compared with a per-channel limit.
Some samples at the end of a step are uncounted and overwritten by the next step.
The independent verifier follows the actual original step accounting and full
decoded predictor history; it does not silently replace this with a different
decoder or a modern decoder's output. Host-core equality is not a new physical
Dreamcast timing measurement.

Verification scope and reproduction
Use jp_port_tools/verify_native_game_loops.py with --workspace, --build, --track
and fresh private --output. The build is the qualified native game-stream graph.
It uses the actual original task scheduler, ADXT/SJD/ADXSTM/GDFS/RNA and supplied
ARM firmware. The disc fixture is an independent read-only oracle, not production
I/O. Provide the matching local Japanese input/firmware yourself; they are never
included in public source or research archives.

inventory_native_game_loops.py takes the same four arguments and produces only
field metadata and hashes, without retail header/audio bytes. Existing reports
remain immutable. The final runtime source was rerun for all four cases after
correcting test observation issues. An earlier invalid producer-pressure fixture
and an overly strict timed observation remain private diagnostic evidence. Only
the confirmed stuck test process was terminated; production code was unchanged.
