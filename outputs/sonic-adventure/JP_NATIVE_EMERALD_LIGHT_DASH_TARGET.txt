Light Dash target selection on Windows

The native build links the target-selection part of the pinned Sonic
Light Dash routine to the retained stage ring lists. It uses the
original cone and nearest-distance rules. The unsigned angle adapter
uses the existing SH-4 numerical helpers and clamps dot-product
overshoot before acos. Exact original angle-boundary parity remains
unverified. The stage diagnostic does not activate Light Dash.

Run build_native_emerald_light_dash_target.py against the qualified
ring reach v2 build. In a fresh Windows process, initialize the Ninja
matrix stack and call jp_light_dash_target_check. A zero return
confirms nearest forward target, stable ties, rear-target rejection,
and player-list separation. The Emerald Coast scene regression
passed 862 checks and matched all eight previous captures.

Movement toward the target, the roll fallback and the Sonic mode
transition are separate dependencies. Overall completion remains
about 10 percent.

The current builder also links the original steering branch after target
selection. It reuses the native atan2 adapter to calculate heading. The
fixture verifies forward speed, both original speed limits, dash-step
extension, and leaving speed alone when no forward target exists.
The scene regression passed 847 checks and reproduced all eight captures.
The rolling fallback, mode transition and live controller activation
remain open. The previous selector-only proof records its own hashes.

The roll build now runs the original rolling acceleration and shared
speed integration when the selected player's nearby-ring list is
empty. It preserves the no-steering branch for a nonempty list with
no forward target. The focused test checks airborne roll acceleration
and rejection of a grounded call without a contact record. The Windows
scene passed 935 regression checks. Controller activation and the live
Light Dash mode transition remain open.

The release build links the ring-dash branch of the original transition.
The focused fixture uses the actual pad record and checks held input,
release, animation, timer, initial speed, guard flags and one-shot
behavior. It also checks that Ancient Light defers to its separate
attack path, which still needs integration. The sound calls are linked;
audible release playback and live controller activation remain untested.
The Windows scene passed 840 regression checks.

The duration build adds the original timer and history-distance stop

The scheduled-mode build exercises release, steering and stop in a
real task scheduler callback. In a fresh process, initialize the
