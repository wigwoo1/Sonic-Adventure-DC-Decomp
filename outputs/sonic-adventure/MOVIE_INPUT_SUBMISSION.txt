Independent expectations check packet bytes and byte order, context/buffer
projections, dispatch for states 1/2/3/4/9 and skipped states, leading/interpacket
padding, all 256 mutex byte values, byte neighbors, purge order, register/FPU
preservation, readiness/busy/lock priority, all 24 command/token records, both
buffer banks, signed clock-product/division/shift and ordered transport writes.
Leading padding reads context +10e4; interpacket padding reads +10c8. The two
fields are distinct. Null, misaligned and rejected bus accesses preserve reached
stack/register/memory effects and pending IDs rather than inventing success.

Each three-phase lifecycle uses a primary unit (0, 6, 12 or 18), a real command
10 or 11 request API, both buffer banks, both word orders and two FPU modes.
The original API creates the queued serial; submission moves that same serial
into flight, clears the queued slot and writes the physical command-buffer
address/start register. The original response pump moves it into the completed
slot and rearms. No completed ID or saved task frame is installed by the test.

Device busy-clear and raw received bytes are explicit external observations.
The unchanged startup-platform bus stores register values; it does not execute
Maple DMA descriptors, acquire a physical controller response, advance physical
device time or automatically deliver completion interrupts. RAM shadow backing
for the transport addresses remains unused. These tests therefore establish the
original software handoff and response path under declared inputs, not physical
device operation or successful active game/movie parsing.
