Animation setup
Entity+11e/+120/+122 halfwords are cleared, entity+138 receives the original
animation table 0ca514d4, entity+118 receives its first record's halfword at +4,
and entity+134 receives raw 1.0 under ordinary narrow transfers. The helper
reads record start/end floats 0.0 and 8.0 and calls existing main RNG 8c10d334.
The original LCG updates the seed by multiplier 1103515245 and addend 12345,
then returns bits 16..30. Using original FLOAT/FMUL/FMAC order and constant
2^-15, the helper writes the random position to entity+124. For the shipped
first record this is exactly RNG_output/4096. It clears the low six bits of
entity+11a while retaining the other bits and neighboring halfwords. MACL is
saved/restored by the reused RNG, with its original visible stack write.
Wide stores can overwrite the animation-table pointer. Invalid reached reads
are guarded before effects, and PR=1 stops at the original FLDI1. Numerical
traps in the JSR delay slot stop before the RNG is invoked while retaining the
already updated PR. No invented random advancement is added on those stops.

Appearance selection
The three signed bytes at appearance+5c/+5d/+5e are classified as:
  less than -35: category 0
  -35 through +34: category 1
  +35 or greater: category 2
The original 27-entry tables use index 3*categoryX + 9*categoryY + categoryZ.
The helper installs original mode/pair bytes and pointer words, calls all three
lower setters natively, and writes ffffffff to entity+7d0/+7d4/+7d8. The lower
setters update entity+804, +808/+80a halfwords and +7f0/+800 words, retaining
neighboring fields. It also installs links at +7e4/+7e8/+7f4. These raw offsets
and table contents are verified; names do not assert complete game semantics.

Accessory installation and shared data
Appearance type 6 skips accessory installation. Type 0 selects table 0c91b890;
other types use 0c91be30. Each table contains 15 original records of 96 bytes.
Seven appearance selection bytes at +4c..+52 use ff for no accessory. The first
three operations replace mesh pointers on nodes 28/29/30. Nine further
operations replace child pointers on nodes 19/21/35/37/2/5/8/10/12, according
to the original slot/kind maps. Null asset entries are skipped.
The routine then whites the B/G/R bytes of each selected source material.
Alpha, material IDs, flags and other bytes are retained. These writes affect
shared original accessory materials in AL_MAIN RAM; they are not limited to
the newly allocated clone. The independent oracle predicts every permitted
shared-data byte change and installed pointer. The original disc/decoded file
bytes are never modified; only per-test/runtime RAM changes.
The test domain uses no accessory (ff) or original IDs 0..14. Invalid arbitrary
IDs are not presented as a supported gameplay contract.

Final material tails
The three outer tail bodies perform their own original list/stack operations.
They select material IDs from palette [217,218,219,220] (appearance+192 values
above 3 clamp to palette index 0), or IDs 158/161, then OR flag 00400000 into
the selected material flags. These helpers share behavior with the previously
recovered inner variants, but are distinct original bodies/addresses and are
byte-checked and tested independently. The caller restores its own saved PR
and registers before tail transfer; nested and outer helper orders are retained.
