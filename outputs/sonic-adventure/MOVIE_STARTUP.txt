Software platform policy
startup_platform_bus.c adds explicit storage for nine system/timer registers
with their reached byte/word/long widths, new word slots in the 005f6800..7cff
window, and 512 cache-array tag words at f4000000 with 32-byte spacing. Only
the newly stored word slots gain physical/P1/P2 aliases. Existing DMA, IRQ
status/mask, context, CCR and raw input routes retain their earlier handlers.
This storage does not deliver interrupts, progress DMA, generate timer ticks,
execute exception vectors, model dirty cache lines/MMU timing or render pixels.

Counter-reset writes are stored. Guest clock reads continue consuming the
existing explicit raw observation stream and do not restart it. The standalone
storage API exposes the stored counter; the host clock-read producer supplies
guest timer observations, as in the previous verification pipeline. The first
regression attempt exposed a reference adapter that shadowed this producer;
it was corrected before qualification. Two actual original-clock comparisons
and five routing checks now verify stream consumption with separate reset state.

Cache P2 aliases move instruction PCs, labels and PC-relative ADDRESS operands.
Loaded literal DATA stays original, including the cached 8c5fc81c helper pointer
called from uncached cache setup. Tests verify that call boundary explicitly.
The separately indexed five-row return tail at 8c5fc0b8 is combined into the
cache-setup listing without rewriting either historical Ghidra export. Shared
tail bytes and alias executions do not create extra recovery credit.

Original vector setup first patches two handler-pointer fields in its source
templates, then copies them to VBR+100/400/600. The independent copy check uses
those original patches. The original cache-purge bases are separate literals:
VBR+400/1000/1800, each with the following 32-byte line. These addresses are
preserved exactly rather than inferred from copy destinations. Cache-purge
operations retain the existing coherent-RAM bus policy.
