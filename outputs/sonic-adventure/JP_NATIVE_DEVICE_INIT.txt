Actual device startup
The complete njInitSystem control flow now runs through native providers. Its
original typed configuration, screen/mode assignments, callback registration
and full global initializer are retained. Console video MMIO/sync loops are
replaced with bounded waits on the actual native logical clock/message pump.
Provider failures stop initialization and are observable through
jp_device_status instead of allowing the original void call to continue.
Source adaptations are recorded explicitly; this is not a byte-matching native
copy of the console hardware procedure.

The new device owner creates a real D3D GPU, DXGI window/swapchain, SDK-backed
video state, native performance clock, logical wait service and presenter.
The first timing boundary occurs before GPU creation, as Ninja's sequence
requires; message service becomes window-aware when the real window exists.
NTSC/VGA use 60000/1001 logical ticks and PAL uses 50. These are native logical
timing domains, not measured physical scanout or console interlaced IRQ timing.
The logical canvas and actual window render dimensions are separate.

Ready, empty queue/frame/texture/render-state owners are prepared by the caller.
They remain caller-owned. Device setup rejects other live video, clock, wait
or presentation owners rather than overwriting them. Live device re-entry and
foreign-thread access cannot replace existing native handles. Borrowed GPU/
window handles are exposed for actual game rendering, and remain owned by the
device service until completed shutdown.

Eight missing original mode/framebuffer objects have one typed frame owner.
The existing _nj_vertex_buffer_ descriptor is exported and reused, not copied.
The original SystemConfig object stays in its existing vertex-lifecycle owner.
The device module imports all state through the native data-import ABI; its
LLVM transform changes linkage only, preserving field types and accesses.
All modules share the same actual clock and kmiDeviceExtension record, with no
circular DLL dependency. Builders inspect existing definitions before adding
state and preserve every existing object.

The complete original kmiFBControl and store_frame bodies calculate native
SDK framebuffer metadata. Their fields are checked against original SH-4 code.
The original configuration points to both actual typed surface descriptors.
Real native rendering uses the owned DXGI buffers. Original legacy VRAM surface
allocation/pSurface addressing is not implemented by this stage, and zero
legacy descriptors do not pretend to expose CPU-mapped swapchain pixels.
RGB565/RGB555/ARGB1555/RGB888/ARGB8888 metadata paths are tested; rendering
continues in the established native RGBA8 backend. Console framebuffer colour
quantization/dithering fidelity is not claimed. Console anti-alias modes are
explicitly rejected until their actual rendering behavior is supported.
Display sizes are bounded by the existing backend limit of 8192, but this
milestone does not qualify full-game 8K or high-FPS performance.

Ownership and cleanup
Partial setup and runtime errors are reported explicitly. The owner drains
pending presenter work before closing window/GPU/video/wait/clock services.
An externally retained frame/job prevents completed shutdown; ownership stays
available for a retry after that caller releases its work. Completed shutdown
is idempotent. Existing queue, texture and frame storage is not destroyed by
the device owner. Device status also surfaces terminal presenter, timing and
video failures after initialization.

The existing general exit service must be adapted before combining its cleanup
authority with this new device owner in full sbInitSystem. Do not pass the new
borrowed GPU/window handles to the old jp_exit_bind as independently owned
resources: that would create duplicate cleanup authority. Integrate one device
cleanup operation or an explicit, verified ownership transfer first.

Presentation count
kmSetWaitVsyncCount now changes actual native presentation scheduling. It
retains the unfinished current countdown and changes its reload count, as the
original contract requires. A ready picture waits for the first eligible
future logical boundary. The countdown advances in constant time even for
large elapsed intervals. Counts below 1 are rejected without altering phase;
the maximum signed count is handled without integer overflow. Default count 1
retains the previously qualified next-boundary behavior. This is progressive
native scheduling, not a full emulation of the console's interlaced slot IRQs.

a read-only x64 peer reads the actual shared native record. No game/SDK body

Ten mode/format cases each initialize the actual device, then run the real
vertex lifecycle, font setup and original game debug-text calls. Ten real GPU

WM_QUIT delivery interrupts pre-GPU startup and permits clean recovery. A

by the device and drained safely. No fake failure/success provider is used.
