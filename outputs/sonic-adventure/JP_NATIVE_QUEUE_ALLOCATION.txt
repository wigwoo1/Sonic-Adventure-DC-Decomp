Native vertex-list allocation milestone
Overall project estimate: about 10%; goal active. Incomplete research build.

What changed
The existing five real renderer queues can now be preallocated together.
This is the allocation foundation needed by native system configuration and
njInitVertexBuffer; those two SDK entry points are not integrated yet.
The byte-matching Japanese baseline remains separate from native-port progress.
English localization, full gameplay and later platforms remain unfinished.

Ownership and behavior
Compile native/jp_native_queue_allocation.c in place of jp_native_queue_direct.c,
never alongside it. It includes the preserved original authored queue layers;
there is one pool set, one SDK cursor table and one frame recording owner.
jp_queue_preallocate accepts five byte minima in jp_queue_list order: opaque,
translucent, punch-through, opaque modifier, translucent modifier. Minima must
be multiples of 32. The owning game thread must have an empty, inactive live
recording. Each list uses actual aligned host memory with its existing guards.
All replacements are staged before any old buffer is freed or changed.
Guard storage and simultaneous old/new buffers count toward the memory budget.
Failures preserve buffers/cursors/contexts/frames and set the usual sticky
queue error. Clear it before retrying. Bigger buffers are retained; zero minima
do not disable a list. Normal checked producer reservation/growth still applies.
No fake console heap allocation, direct TA pointer, or P1/P2 alias is returned.
Submitted frames retain independent owned bytes across queue replacement.

Verification
249 allocation/lifetime checks exercise both production code and a separate
private diagnostic build. The latter forces allocation failure at each of the
five staging positions and checks temporary cleanup and retry. Its hooks are
not compiled into the production owner or packaged library.
8,573 complete frame/resource-lifetime regression checks passed, including
193 submissions and 128 actual original producer draws.
591 original Japanese save-layout/default/CRC comparisons passed.
7,732 real startup/reset/logo/exit/EOR checks passed: 570 GPU-rendered frames
and Presents, with independent image comparisons across 175,104,000 pixels.
Total: 17,145 checks. Startup's native caller requests opaque 416 bytes and
translucent 655,360 bytes, corresponding to the main request's host minima.
This proves the allocations are actually used by the renderer. It does not
claim the original njInitVertexBuffer or full system_boot_init ran.
Actual startup screenshots are captured privately and can be shared in chat.

Public/private boundary
The new public support library contains exactly one authored queue object.
All historical published source/proof/build bytes remain preserved. Complete
SDK/game-containing DLLs, retail font/texture inputs and captures remain private.
Research artifacts are not a playable PC port and contain no playable EXE.
